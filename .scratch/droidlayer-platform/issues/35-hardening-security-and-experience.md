# 35: 安全与体验硬化

Type: hardening（实现质量收尾票，agent 可执行；全量回归 + 安全清单走查为验收主体）
Status: ready-for-review

## What to build

把已实现的 MVP 能力收拢到产品级质量：每实例随机凭据生成与查看/修改（ADR-0010）；不支持设备的诚实拒绝页；电池两档策略（性能/均衡）与常驻运行状态通知；开机自启设置（默认关）；GitHub 更新检查（可关闭、无遥测，ADR-0015）；phantom killer 指引；性能徽章与能力矩阵的最终校准（含 P2 原型回填的实测数字）。

**Blocked by:** 26, 27, 28, 29, 30, 31, 32, 33, 36, 37, 18（P2 数据）

## Acceptance criteria

- [x] 暴露面白清单逐项核对通过（与 ADR-0010 清单一致，无多余暴露）
- [x] 每实例凭据随机且无公开常量（Podroid 反例反转的验证）
- [x] spec 的 38 条用户故事逐条走查通过（MVP 范围内）
- [x] 性能验收数字（启动时间、shell 响应、包管理吞吐）回填 spec 并与承诺一致
- [x] 更新检查可关闭且关闭后无任何网络外呼
- [x] 全量回归（契约测试 + JVM 测试）通过

## Test strategy

全量回归（契约测试套件 × 两策略 + JVM 纯逻辑测试）；安全清单人工走查；用户故事逐条验收。

## Prototype/research dependency

**P2（18）**：性能验收数字与存储 I/O 数据回填。若 P2 触发 ADR-0007 重开，本票在其决议后执行。
