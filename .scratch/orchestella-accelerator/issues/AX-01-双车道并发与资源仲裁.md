# AX-01: 双车道并发与资源仲裁

- Type: implementation
- Status: ready-for-human
- Priority: P0（交火地基）
- Owner: runtime coordinator owner
- Blocked by: PL-01（预热池接口）
- Parent: `../决策地图.md`
- Zero-device: 是

## 背景

交火要求 QEMU Full Lane 与加速 VM 同时运行。现有 `RuntimeProcessSupervisor` 只覆盖单运行时；两个 VM 同时存在时，CPU/RAM 预算、启动顺序、停止顺序、租约、崩溃恢复都没有统一 owner。Podroid 目前是单 VM（issue #91），并发正是我们要建立的结构性差异。

## 目标

- 新增 `DualLaneCoordinator`，是两条车道的唯一准入与停止 owner。
- 明确预算、启停顺序、降级与崩溃语义；任何失败都不得留下孤儿进程或悬空 lease。
- 不改变单车道已有的 stop 语义（`CONFIRMED` / `UNCONFIRMED` / `ALREADY_STOPPED`）。

## 任务

- [x] 定义 `Lane`（QEMU / ACCEL）与 `LaneState`；协调器持有两套 runtime handle。
- [x] 准入：CPU 核数、RAM MiB、磁盘 GiB、加速器是否可用；拒绝时返回固定 reason code。
- [x] 启动策略：默认并行启动；编译任务等待 accelerator `READY`，超时则本地编译，不阻塞桌面。
- [x] 停止策略：QEMU 先停、加速器后停；QEMU 停止失败仍要尝试停加速器；加速器崩溃不拖垮 QEMU，标记 `ACCEL_LOST`。
- [x] 崩溃/超时：进程死亡、heartbeat 丢失、stop 超时；保留 `UNCONFIRMED`，不删除 lease。
- [x] 幂等：重复 start/stop、并发 stop、启动中途取消。
- [x] 事件：`lane_started` / `lane_ready` / `lane_stopped` / `lane_lost` / `budget_rejected`，只含计数、耗时、固定 code。
- [x] fake 进程/时钟测试不少于 15 例；覆盖双启、双停、启动竞态、预算拒绝、加速器崩溃、QEMU 崩溃、取消。
- [x] 文档：状态机图、预算换算、与 `RuntimeProcessSupervisor` 的职责边界。

## 边界

- 不实现第二套 stop 逻辑；所有进程停止必须经 `RuntimeProcessSupervisor`。
- 不在本票实现选道策略（AX-02）或通道协议（AX-03）。
- 不把“并行启动”写成“并行可用”；可用性以 AX-02 的 decision 为准。
