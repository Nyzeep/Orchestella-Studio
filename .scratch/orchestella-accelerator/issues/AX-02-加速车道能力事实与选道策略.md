## 背景

现有能力路由只回答 Full/Fast/Auto，没有回答“这台设备能否同时跑加速车道”。Podroid 的后端切换依赖用户选择与运行时失败，缺少显式的能力事实与 reason code；我们要把“为什么不可用”变成产品可见、可测试的决策。

## 目标

- 统一能力事实：AVF 是否存在、protected/non-protected 支持、加速镜像是否存在、vsock 是否可用、编译器身份是否匹配、热/电状态是否允许。
- 输出唯一 decision：`QEMU_ONLY` 或 `QEMU_PLUS_ACCEL`，附固定 reason code；禁止静默降级。
- 决策是纯函数，可在 JVM 上穷举。

## 任务

- [x] 定义 `AcceleratorFacts`：`avfPresent`、`nonProtectedSupported`、`protectedOnly`、`acceleratorImagePresent`、`vsockSupported`、`compilerTriple`、`thermalState`、`batteryState`。
- [x] 定义 `AcceleratorDecision`：`mode`、`reasonCode`、`degradedCapabilities`。
- [x] 选道规则：
  - 无 AVF / 仅 protected → `QEMU_ONLY` + `ACCEL_UNAVAILABLE_NO_NON_PROTECTED`；
  - 有 non-protected 但镜像缺失 → `QEMU_ONLY` + `ACCEL_IMAGE_MISSING`；
  - 编译器 triple 不匹配 → `QEMU_ONLY` + `COMPILER_MISMATCH`；
  - 热/电不允许 → `QEMU_ONLY` + `THERMAL_BUDGET`；
  - 全部满足 → `QEMU_PLUS_ACCEL`。
- [ ] 事实提供者接口：真实 Android 实现 + fake 实现；测试只依赖 fake。**当前批次只交付接口 + fake；真实 Android provider 后置。**
- [x] 与 PL-01 的预热池联动：池不可用不等于加速不可用，decision 只看事实。
- [x] truth table 不少于 12 组，覆盖 protected-only、non-protected、镜像缺失、编译器不匹配、热限制。
- [x] golden JSON：decision 序列化稳定，供 UI 与日志复用。
- [x] 文档：能力矩阵、reason code 表、用户可见文案（不得写成 Full Linux 或“硬件加速整机”）。

## 边界

- 不根据设备型号硬编码；只根据运行时事实。
- 不把 protected 车道当作加速器；protected 只贡献控制面/预热。
- 不在本票实现通道或 distcc。
