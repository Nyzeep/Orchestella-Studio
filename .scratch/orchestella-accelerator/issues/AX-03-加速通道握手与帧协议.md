## 背景

`DistccTcpVsockBridge` 目前只做字节泵：没有版本、没有鉴权、没有能力协商、没有帧边界、没有背压。交火需要一条可诊断、可拒绝、可重连的通道，否则编译器不匹配或旧版 payload 会被当成“编译失败”。

## 目标

- 定义 `AXP1` 协议：握手、能力协商、鉴权、数据帧、结束、重置、心跳。
- 传输与协议解耦：vsock 与 TCP 共用同一编解码；测试用内存传输。
- 失败必须 typed，客户端可回退本地编译。

## 任务

- [x] 定义握手：magic `AXP1`、协议版本、随机 nonce、32 hex token、`role=host|guest`。
- [x] 能力协商：`distcc`、`max_frame`、`compiler_triple`、`arch`、`features[]`；未知能力忽略但记录。
- [x] 帧格式：`HELLO` / `HELLO_ACK` / `DATA` / `EOF` / `RST` / `PING` / `PONG`；长度前缀，最大帧默认 1 MiB。
- [x] 鉴权：常量时间比较；失败返回 `AUTH_FAILED`，不泄露期望值；握手超时 3 秒。
- [x] 背压：接收窗口 4 MiB；窗口耗尽暂停读；慢消费者不得无限堆内存。
- [x] 半关闭：`EOF` 只关闭发送方向；`RST` 立即双向关闭；重复关闭幂等。
- [x] 重连：指数退避（100ms 起，上限 2s，最多 3 次）；只在握手前重试，数据传输中不重试。
- [x] 错误码：`VERSION_MISMATCH` / `AUTH_FAILED` / `FRAME_TOO_LARGE` / `PROTOCOL_ERROR` / `TIMEOUT` / `CLOSED`。
- [x] 测试：golden vectors、半包/粘包、1 MiB 与 16 MiB 流、窗口耗尽、reset 竞态、版本不匹配、鉴权失败、恶意长度。
- [x] 日志：只记 code、字节数、耗时；不记 token、argv、源码或对象正文。

## 边界

- 不解析 distcc 协议；`DATA` 对上层是透明字节流。
- 不引入新的序列化框架；保持零依赖或仅 JDK。
- 不改 FLN1 wire；AXP1 是独立协议。
