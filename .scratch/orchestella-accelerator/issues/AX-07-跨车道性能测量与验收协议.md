# AX-07: 跨车道性能测量与验收协议

- Type: verification/tooling
- Status: ready-for-agent

- Owner: performance owner
- Blocked by: AX-06

- Zero-device: 是

## 背景

DV-03 只写了“n≥10、median/IQR、≥1.5x”，没有可执行的采集器与结果 schema。没有预注册的测量协议，真机测试很容易变成“感觉快了”，也无法与 Podroid 做可比较的结论。

## 目标

- 一个可在宿主 dry-run、在设备上直接执行的性能采集器。
- 固定场景、固定统计口径、固定失败分类；结果可归档、可比较。
- 明确停止条件：不达阈值就记录负结果，不改默认、不做产品声明。

## 任务

- [ ] 场景定义：
  - 冷启动到 ready；
  - 小项目编译（单文件/10 文件）；
  - 中等项目编译（100 文件，`-j1`/`-j2`/`-j4`）；
  - 本地编译 vs 交火编译的端到端墙钟。
- [ ] 统计：n≥10，median、IQR、min/max；记录失败样本，不剔除。
- [ ] 指标：墙钟、预处理/传输/编译/链接拆分、卸载率、重试次数、回退次数、峰值内存。
- [ ] 结果 schema：`accelerator-perf-v1.json` + `validate.py`；字段含 scenario、mode、n、median_ms、iqr_ms、failures、device_alias、build_id。
- [ ] 宿主 dry-run：用 fake runner 生成完整报告，验证 schema 与统计函数。
- [ ] 设备 runbook：安装、启动、采温、控温、同资源、同镜像、失败重跑规则。
- [ ] 对比基线：QEMU-only、QEMU+ACCEL；可选 Podroid 同场景（只记公开可复现参数，不逆向其内部）。
- [ ] 停止条件：端到端 <1.5x → 不产品化；任一场景回归 >5% → 回退该变体。

## 验收命令

```bash
python -m pytest tools/accelerator-perf -q
python tools/accelerator-perf/validate.py --self-test
```

## 边界

- 不把 Fast Lane 内部编译时间当端到端；不把 fake 数据当性能结论。
- 不采集设备序列号、型号、账号、路径；只用别名与 build_id。
- 不在本票调 QEMU 参数；P08 的调优另有票据。
