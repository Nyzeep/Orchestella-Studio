# AX-08: 设备前生产装配与探针

- Type: integration
- Status: ready-for-human
- Priority: P0（DV-ACC 前置）
- Owner: app integration owner
- Blocked by: AX-01、AX-02
- Parent: `../决策地图.md`
- Zero-device: 是

## 背景

批次三完成后，AX-01 的 `DualLaneCoordinator`、AX-02 的 `AcceleratorPolicy` 都只有测试内装配：

- `AcceleratorFactProvider` 只有 fake，没有 Android 实现；
- `QemuLaneRuntime` 的 readiness 默认恒 false，没有生产探针；
- `new DualLaneCoordinator` 在 `app/src/main` 中没有调用点；
- `ProtectedWarmPool` 也没有生产实例。

如果直接进入真机，唯一能跑的还是 QEMU 单车道；交火协调器和选道逻辑无法被设备验证。本票补齐“设备前装配”，全部可用 fake 完成验收。

## 目标

- 用现有 AVF 能力事实实现 Android `AcceleratorFactProvider`，不重复造能力检测。
- 为 QEMU 提供独立 readiness 探针，禁止再用进程存活代替 guest 就绪。
- 在 app 装配根构造 `DualLaneCoordinator` + `ProtectedWarmPool`，默认关闭，行为与今天一致。
- 所有失败走固定 reason code；决策为 `QEMU_ONLY` 时不得启动加速车道。

## 任务

- [ ] 盘点现有事实源：`AvfPlatformFacts`、`AvfCapabilityEvaluator`、`HostHardwareDetector`、加速镜像 manifest、vsock 能力、热/电 API。
- [ ] 实现 `AndroidAcceleratorFactProvider`：
  - `avfPresent` / `nonProtectedSupported` / `protectedOnly` 来自现有 AVF 能力；
  - `acceleratorImagePresent` 来自私有镜像/manifest；
  - `vsockSupported` 来自平台/内核事实；
  - `compilerTriple` 来自加速镜像 manifest；
  - `thermalState` / `batteryState` 来自 Android API；
  - 未知一律保守拒绝。
- [ ] 定义 `QemuReadinessProbe`：从现有启动链路（`InstanceLaunchSequence` / session ready 事件）取 guest 就绪；没有信号时显式 `UNKNOWN`，不得回退到 `isAlive`。
- [ ] 装配根：
  - feature flag 默认关闭；
  - 关闭时只构造 QEMU 单车道；
  - 打开时按 `AcceleratorDecision` 决定是否启动 ACCEL；
  - `ProtectedWarmPool.Admission` 接同一预算账本，池容量仍默认 0。
- [ ] 事件与状态：复用 `LaneEvent` 固定 code；新增 reason 时同步 AX-02 表。
- [ ] 测试（fake）：
  - 无 AVF/仅 protected → 只启 QEMU；
  - non-protected + 镜像 + vsock + triple + 热/电 → 双车道；
  - 镜像缺失/编译器不匹配/热限制 → QEMU_ONLY；
  - readiness 未置位 → QEMU 保持 STARTING；
  - flag 关闭 → 不构造 ACCEL、不消耗预算。
- [ ] 文档：装配图、flag、设备前置、如何读 reason code；不写 UI 方案。

## 边界

- 不接设备、不启动真实 VM、不改 UI 信息架构。
- 不重复实现 AVF 能力检测；复用现有 seam。
- 不把 protected 车道当加速器；不改变 AX-01 的停止顺序。
- 不改变默认产品行为；flag 关闭时与当前版本一致。
