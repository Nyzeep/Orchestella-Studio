# Linux 工作站品质优化实施规格

Status: ready-for-agent
Date: 2026-10-13
Input: 用户本轮明确请求、quality-20261013-map.md、三个并行研究票。

## 目标与保留

以当前原创 VM-first 架构与良好的构建主义 UI 为基础，修复 Linux 可用性、终端交互和界面真实性。所有变化在共享工作树本地实现与测试，提供可安装 debug APK，不发布、不清除数据。

## 验收行为

1. App 首次打开直接显示工作站，用户主动创建实例时才出现发行版/硬件配置。
2. 每次装配保留真实发行版 init，Ubuntu/Debian 等基础 rootfs 必需包安装完成且验证后才能写 ready；安装失败明确保留 failed/retry 状态，绝不能提前写 .firstboot-done。已有系统服务/用户配置不被通用脚本覆盖，已有根盘缺少marker也不会自动格式化。
3. 基础环境包含实际包管理器、网络/DNS、CA证书、常用文件/网络工具、UTF-8 与发行版服务管理能力；验证已验 gvproxy NAT 不回归。SSH凭据保持每实例随机、宿主不自动LAN暴露。
4. 下载使用manifest锁定大小/SHA256，校验 metadata 传至 guest，未知或缺校验输入失败即停。默认root用户配置不得生成公开固定密码。
5. 终端支持组合IME、完整UTF-8分包、真实shell Tab、Ctrl/Alt及箭头、粘贴、选择复制与上滚查看；新输出不得夺走正在阅读的历史位置。会话重连不清空/丢失/串流输出；显示真实连接状态。
6. 原创VT屏幕解析支持top/vim代表性的光标定位、擦除、滚动区域和alternate screen。尺寸在键盘/横竖屏/字体变化后通过既有鉴权控制通道回传，只有一个control reader。不能据纯序列测试声称所有应用完全兼容。
7. 主题切换影响完整页面chrome、弹窗、动态实例卡片与终端，自定义背景/字号/间距/光标设置持久化并真实生效，保持既有构建主义几何与状态色。
8. 首页删去假终端、假按键、固定FPS/延迟/CPU/温度/IOPS，提供真实终端/日志/端口/冷备份入口。硬件数据在前台周期刷新（后台停），CPU若系统不可读取则明确显示不可用，以真实核心数/VM配置呈现；不填假值。SSH只基于实际已配置映射显示。
9. 在实际USB真机构建安装验证主题、首页刷新、键盘和实例启动，保留截图、日志摘要和APK checksum。每个发行版的未跑场景如实标记。

## 用户追加验收（2026-10-13）

- 当前目录所有参考仓库仅拉取与本地分析，不向参考上游或本项目远端推送任何内容。
- 各 catalog 支持的发行版逐项检查固定输入、真实原生 init、软件源、基础包、证书/UTF-8、网络、服务与重启；已运行、静态检查、未验证必须分别记录。设备 AVF 能力或未实现的桌面/硬件能力不能被“完整可用”文案掩盖。
- 提交后的真实 shell 命令在历史中保留，不能被 readline 的擦除/光标序列抹掉；用户名/路径提示、用户命令与输出以空行分段，命令使用当前主题下可读的高对比强调颜色。
- 提示符后的输入区由明确 shell 标记识别，不按 `>`、`❯` 或输出文本猜测。输出不得混入该区。终端备用屏幕与全屏程序仍遵循原生 VT 网格，不人为插行/改写程序颜色。
- 首次控制握手需要覆盖 QEMU 装配时间与 guest agent 重启，采用同协议、同 token 的幂等校验和有期限重试；普通控制请求保留短超时，唯一读取者不变。
- 用户追加：修复终端偶发自行跳到顶部/不受控滚动；阅读中追加输出、键盘与尺寸变化应保持明确锚点，跟随状态才自动到最新输出。
- 用户追加：真实 `clear` 清屏必须生效，快捷栏首屏提供直接可见的 CLEAR。显式清屏建立新的显示区间，不删除 shell 命令历史或运行日志；备用屏幕程序保持原生控制语义，不能被普通输出更新误清屏。

## 实施所有权与检查

- guest worker：guest-assets/init、app resources guest_init、firstboot/provision脚本与测试。
- terminal worker：终端实现、原创VT模型、PersistentTerminalSessionPool、最小bridge resize seam与测试。
- theme worker：ui/theme、设置存储/设置页、主题测试。
- trust worker：EmbeddedProvisionInput、实例默认凭据、QemuRuntimeBootstrapper信任链与测试。
- coordinator：首页、布局、运行状态整合、联网参考研究、Gradle与真机验收、最终独立审查。

整合先运行针对改动的JVM/contract检查与guest脚本语法，再构建debug APK。真机失败按日志定位修复后再试，不以构建成功代替运行验收。
