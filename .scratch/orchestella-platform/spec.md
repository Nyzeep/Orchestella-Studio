# DroidLayer MVP — 产品规格（Spec）

Labels: ready-for-agent
Version: 1.0（2026-09-05）
依据：ADR-0001 ~ ADR-0016 + CONTEXT.md 词汇表 + docs/research/ 六份研究 + 原型票待办项
变更纪律：本 spec 的每个承诺可追溯到 ADR；研究/原型的新证据若推翻决策，须先重开对应 decision 票，不得静默修改。

## Problem Statement

Android 用户想在手机上使用完整的 Linux 环境——真实的包管理、容器、systemd、编译工具链——但现有选择要么要求 Root 且安全边界薄弱（特权容器路线），要么是无真实内核的模拟环境（用户态兼容路线），要么性能不可接受。同时，硬件虚拟化（AVF/pKVM）已经是 Android 平台能力，却没有以"无 Root、可信任、面向普通技术用户"的方式被包装成产品。

## Solution

**DroidLayer**：一个无需 Root 的 Android 应用，把"完整的 ARM64 Linux 用户空间"作为产品交付。每个 Linux 环境（实例）拥有自己的内核，运行在硬件虚拟化（AVF/pKVM，需一次性授权解锁）或软件虚拟化（QEMU/TCG，全设备兜底）之上；两种执行方式对用户不可见，只以性能徽章区分。容器能力（Podman/Docker/LXC、systemd、namespace/cgroup）全部在 guest 内部解决。发行版以官方 rootfs 装配，新增发行版只需新增一条清单数据。用户通过终端使用实例；实例数据持久、可导出、可恢复。

## User Stories

1. 作为 Android 用户，我想安装一个无需 Root 的应用并在其中运行拥有自己内核的真正 Linux，以便在手机上使用完整的 Linux 工具链而不牺牲设备安全模型。
2. 作为任意 arm64 设备的用户，我想安装后即可创建并启动 Linux 实例（软件虚拟化档），以便零门槛获得可用的 Linux 终端。
3. 作为 AVF 设备用户，我想通过应用内授权向导完成一次性授权，以便解锁硬件虚拟化的近原生性能。
4. 作为授权向导的用户，我想先看到设备能力检测结果（支持/缺什么），以便不执行注定失败的操作。
5. 作为不支持硬件虚拟化的设备用户，我希望应用根本不展示授权引导，以便不被误导。
6. 作为 RAM 低于 3GB 的设备用户，我想在创建实例前被告知设备不支持及原因，以便不得到一个频繁崩溃的假体验。
7. 作为新手用户，我想看到每个实例的性能徽章（硬件加速 / 软件模拟·较慢），以便对性能有正确预期。
8. 作为用户，我想从发行版目录中选择 Alpine 或 Debian，以便在轻量快速与完整生态之间选择。
9. 作为弱网用户，我想在下载发行版镜像时看到进度并可重试失败，以便最终完成首次创建。
10. 作为离线优先的用户，我想在安装应用后无需网络即可创建实例（内核等资源随应用分发），以便在弱网环境下也能开始。
11. 作为用户，我想让首次引导自动完成磁盘装配与系统初始化，以便无需任何手动分区/格式化知识。
12. 作为用户，我想在实例就绪后立即进入 root shell，以便马上开始工作。
13. 作为用户，我想在 guest 内使用发行版自己的包管理器安装软件与升级系统，以便像在 PC 上一样维护我的 Linux，且应用升级永不破坏我的环境。
14. 作为用户，我想让 guest 默认就能访问外网（出站 NAT），以便包管理器开箱即用。
15. 作为用户，我想创建端口转发规则并在本机访问 guest 的 web/开发服务，以便把手机当开发服务器用。
16. 作为注重安全的用户，我希望转发规则默认仅绑定本机，以便不意外把服务暴露给局域网。
17. 作为进阶用户，我想显式开启局域网暴露并看到安全提示，以便在知情的前提下共享服务。
18. 作为用户，我想在实例运行时增删转发规则而无需重启，以便随时调整服务端口。
19. 作为用户，我想只读访问设备 Downloads 目录中的文件，以便把下载的文件直接用于 Linux 工作。
20. 作为用户，我想在 guest 任务完成时收到 Android 通知，以便长任务不必盯屏。
21. 作为用户，我想从 guest 内打开 Android 上的链接，以便无缝衔接移动端操作。
22. 作为用户，我想优雅关闭实例（数据完整落盘），以便避免文件系统损坏。
23. 作为用户，我想在应用被系统杀死后重新打开时一键恢复实例，以便中断的工作可以继续。
24. 作为用户，我想看到实例"异常终止"的标记与诊断日志导出入口，以便报告和排查问题。
25. 作为用户，我想在性能与均衡两档电池策略间选择，以便按场景取舍续航与算力。
26. 作为用户，我想看到常驻的运行状态通知，以便随时知道实例是否在运行。
27. 作为用户，我想锁屏后实例默认继续运行，以便长编译/长任务不被打断。
28. 作为用户，我想把实例导出备份到设备上任意位置，以便换机或重装应用时不丢数据。
29. 作为用户，我想为实例扩容磁盘，以便安装更多软件。
30. 作为用户，我可以创建多个实例并保存为已停止状态，以便试用不同发行版。
31. 作为用户，我想在多个已停止实例间切换（停止当前 + 冷启动目标），以便管理多个环境。
32. 作为注重安全的用户，我想看到我的实例使用哪一级隔离（硬件级/进程级）的明确说明，以便理解 guest 与手机之间的真实边界。
33. 作为注重安全的用户，我想实例凭据是随机生成且可查看/修改的，以便确信没有公开的后门凭据。
34. 作为用户，我想应用升级不触碰任何已创建实例的内容，以便升级应用零心理负担。
35. 作为用户，我想在设备重启后按设置自动恢复上次运行的实例，以便服务器场景可用。
36. 作为用户，我想检查 GitHub 上的新版本，且可以关闭这个检查，以便保持完全无遥测的使用方式。
37. 作为用户，我想在 guest 内使用容器（Podman/Docker）运行服务，以便把"同时要多个环境"的需求交给容器而不是多个虚拟机。
38. 作为遇到授权失败的用户（特定厂商设备），我想得到清晰的失败原因与替代路径，以便最终完成硬件加速解锁。

## Implementation Decisions

以下决策均有对应 ADR，spec 只重述产品级承诺，不涉及文件与代码结构。

**运行时架构**
- 两层 Runtime 类别：Full Linux Runtime（产品主体）与 Userspace Compatibility Runtime（定义为正式能力等级，MVP 不交付）（ADR-0001）。
- Full Linux 内部 VM-first：硬件虚拟化（AVF/pKVM）优先、软件虚拟化（QEMU/TCG）兜底；二者是同一类别下的执行策略，共享同一产品契约，实例可在策略间互换（ADR-0001/0002）。
- 平台层 / Full Linux 契约 / 策略专属增强三层划分；能力差异只允许以能力矩阵数据表达，上层禁止执行策略分支；契约测试套件对所有策略运行（ADR-0002）。
- 全部实例元数据携带 runtime 类别与生命周期状态；实例在创建时归属唯一类别（ADR-0001/0016）。

**无 Root 与授权**
- 三级承诺：L1 安装即用（软件虚拟化）；L2 一次性开发级授权解锁硬件虚拟化；L3 OEM 级仅愿景（ADR-0003）。
- MVP 出厂 L1+L2；L2 授权向导先检测后引导（Shizuku 优先、ADB 命令兜底），检测不通过则不展示；授权失败是一等场景，需按厂商提供分步指引与替代路径（ADR-0003；研究：国产 OEM ADB 门控矩阵）。
- 目标用户：技术早期采用者；增长叙事不按大众产品书写（ADR-0003）。

**兼容性地板**
- L1 minSdk 26（Android 8）；L2 纯运行时检测无独立版本门槛；仅 arm64-v8a；RAM ≥ 3GB 且存储余量达标方可创建实例；低于地板诚实拒绝，不留降级假象（ADR-0004）。
- 模拟器环境给出清晰提示（ADR-0004）。

**Guest 内核与发行版**
- 单一 pinned 内核版本、两个执行策略共用；必选能力清单进构建校验（缺项即失败）；CI 可复现构建、全输入校验；MVP 随应用分发并附 SHA256 自检（ADR-0005）。
- 发行版 = 清单数据（DistroManifest：来源/校验/init 期望/按类别能力说明/风味）；rootfs 输入为官方 tarball；实例根盘由首次引导在 guest 内自动装配（Provisioning）；首批 Alpine + Debian；OCI 出 MVP（ADR-0006）。

**存储**
- raw 稀疏单根盘，两个执行策略同格式；系统升级发生在 guest 内；扩容进 MVP；快照不进 MVP；经存储访问框架导出备份进 MVP；镜像全部存于应用私有目录并排除系统自动备份（ADR-0007）。

**网络**
- 默认出站 NAT；入站仅经显式端口转发规则（协议/宿主端口/guest 端口/绑定范围），默认绑定 127.0.0.1，局域网暴露须显式选择并提示；规则持久化、可热更；两个执行策略语义一致（ADR-0008）。
- IPv6、VPN 共存、host mode 为不承诺的非目标；VPN 行为标注"未验证"（ADR-0008）。

**宿主↔Guest 集成**
- 单一传输无关、版本化的桥接协议 + per-VM 鉴权令牌（装配时注入）；MVP 命令集：连接协商、终端尺寸、转发规则增删、通知、打开链接、优雅关机（ADR-0009）。
- 控制面与数据面分离：文件共享走独立数据通道（9p 家族），MVP 仅只读共享 Downloads；宿主向后兼容 N-1 版 guest agent（ADR-0009）。

**安全**
- 隔离承诺三级分述：硬件级（L2）/ 进程级（L1）/ 无实质隔离（未来兼容模式）；guest root 仅触达暴露面白名单（当前：桥接命令 + 只读 Downloads + 本机转发默认值）；每实例凭据随机生成；残余风险清单写入产品文档；安全承诺只加码不减码（ADR-0010）。

**生命周期**
- 前台完全可靠；后台尽力而为（前台服务 + 唤醒锁 + 忽略电池优化引导 + 厂商查杀风险如实告知）；应用进程死亡 = 实例停止，但实例状态持久化 + 一键冷恢复；异常终止标记与诊断路径；重启默认不自启（可选自启）；性能/均衡两档电池策略；热恢复不进 MVP（ADR-0011）。
- 宿主侧进程模型刻意收敛以规避系统子进程猎杀；官方关闭开关仅作指引不作前提（ADR-0011）。

**产品形态与渠道**
- MVP 终端 only，不含任何图形能力；图形走 M2（VNC 软渲染 + 完整输入/IME）→ M3（Wayland 评估）→ M4（GPU 加速，以原型证实第三方可用为前置）里程碑（ADR-0012）。
- USB 直通与音频不进 MVP（ADR-0013）。
- MVP 单运行实例：同时最多一个运行实例，多个已停止实例并存，切换 = 停止当前 + 冷启动；实体模型 Distro ≠ Image ≠ Instance ≠ Session 不合并，单运行是会话↔实例配对约束而非实体合并（ADR-0016）。
- 发布：GitHub 首发、F-Droid 第二渠道、Play 观望；更新检查可关闭、无遥测；首版建立长期签名密钥管理（ADR-0015）。

**许可证**
- 项目代码 Apache-2.0；对 GPL 参考项目零代码复制（借鉴架构、实现全自研）；随应用分发的 GPL 二进制（内核、QEMU）以 CI 生成的对应源码清单履行义务；App 代码 / 随包 GPL 二进制 / guest rootfs 三个分发单元互不传染（ADR-0014）。

## Testing Decisions

- **主测试 seam：Full Linux 契约**（ADR-0002）。这是本项目唯一的深层 seam：所有执行策略行为测试都针对该契约编写，同一套契约测试对硬件虚拟化与软件虚拟化两个实现运行。测试只验证外部可观察行为（实例生命周期、终端通道、转发语义、装配流程、桥接命令），不测实现细节。
- **纯逻辑决策在 JVM 层测试**：引擎选择（能力矩阵 → 执行策略映射）、DistroManifest 校验、转发规则对账、实例状态机、授权向导的状态判定。这些是纯函数级 seam，快速且稳定。
- **能力矩阵是数据不是代码**：矩阵条目变更以数据测试覆盖（某策略声明某能力 → 上层可观察到对应行为徽章）。
- **契约的行为等价性测试**：同一操作（建转发、优雅关机、装配）在两个策略上产生语义一致的结果——这是 ADR-0002 三纪律的测试表达。
- **设备侧行为不进自动化测试，进原型验收**：AVF custom VM 实际网络/GPU/实例身份行为、私有目录存储的随机写性能、TCG 实测性能——由两张原型票产出验收数据，回填 spec 的"待实测"条目。
- 目前无既有测试先例（全新仓库），契约测试套件本身即为第一份先例资产。

## Out of Scope（MVP 明确非目标）

- Userspace Compatibility Runtime 的交付（PRoot 等；等级已定义，交付待用户需求与数据，ADR-0001/研究票 22）
- 任何图形能力：GUI、VNC、Wayland、GPU 加速（ADR-0012，里程碑 M2–M4 属后续版本）
- USB 直通与音频（ADR-0013）
- 快照；IPv6；VPN 共存承诺；guest 融入局域网（host mode）
- 多实例并发运行（ADR-0016）
- VM 独立于应用进程存活；内存态热恢复（ADR-0011）
- Google Play 渠道（ADR-0015）
- x86 / 非 ARM64 架构（ADR-0004）
- 剪贴板同步、麦克风、截图等桥接扩展命令（ADR-0009）
- 任何遥测与云端服务（ADR-0010/0015）
- guest 内图形桌面环境、中文本地化之外的 i18n（后续版本）

## Further Notes

- **待原型回填的条目**（spec 引用处已标注）：AVF custom VM 网络/GPU 可用性、应用更新对 VM 实例身份的影响（原型票「AVF 端到端验证」，需用户真机）；私有存储随机写性能与 TCG 实测数字（原型票「QEMU TCG 实机基线」）。前者数据可能影响存储/OTA 相关决策的重开评估，后者决定性能章节验收数字。
- **证据基线**：docs/research/ 下六份研究（AVF 边界、Podroid 源码、Terminal 参考实现、许可证盘点、国产 OEM、PRoot）。
- **实施期选型遗留**（不阻塞 spec，实现时记录）：终端组件选型（须 Apache 兼容，禁 GPL 系）；HiddenApiBypass 类库默认不引入、纯反射优先；桥接协议编码与错误模型细化。
- **竞品/参照**：Podroid（验证模式、吸取其教训清单）、Android 16 官方 Terminal（特权上限参照物，docs/research/2026-09-05-android16-terminal-参考实现.md）。
