# Full Linux 契约：策略中性的三层划分与三条纪律

Full Linux Runtime 内部，AVF 与 QEMU 的差异被一个**策略中性产品契约**完全挡在上层之外（UX、发行版、桥接、实例管理永不感知当前执行策略）。架构分三层：

1. **平台层**（Runtime 类别无关）：发行版/rootfs 管理、终端 UX、实例元数据、能力徽章/能力矩阵。
2. **Full Linux 契约**（策略中性）：实例生命周期、控制台/终端通道、端口转发语义、共享目录语义、桥接协议、磁盘镜像存储模型——**契约内零策略专属类型**。
3. **策略专属增强**（声明制，永不进契约）：USB 直通（当前仅 QEMU 可行）、GPU 配置（AVF，未验证）、QMP 控制（QEMU 内部）、AVF 反射细节。

三条纪律：**能力差异只许以能力矩阵数据表达**（上层禁止策略分支，能力矩阵是 UI 徽章唯一数据源）；**契约测试套件从第一天存在并对所有执行策略运行**；**契约 v0 只固化已被研究/原型验证的部分**，未验证条目标注"待原型"、允许契约迭代。

## Considered Options

- **按 backend 各写各的（否决）**：Podroid 现状；其作者自认"后端非对称是第一大 bug 源"，且 `qmpClient`（QEMU 专属）泄漏进 `VmEngine` 接口是现成反例。
- **契约缩到最小公分母（否决）**：等于把 USB 直通等单边真实能力从产品中删除；"契约 + 显式增强声明"结构在保持中性同时保留能力。

## Consequences

- UX / 桥接 / 发行版层禁止出现执行策略分支；review 时接口出现策略类型即否决。
- 新执行策略接入 = 实现契约 + 通过契约测试 + 声明能力，不改上层。
- AVF 端到端原型（原型票）可能推翻契约细节：未验证条目允许迭代，契约以版本演进，不追求一次定死。
- 性能不对称不因契约而消失（5–20× 差异永存），性能徽章常驻。
