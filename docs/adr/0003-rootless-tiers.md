# 无 Root 三级承诺：MVP 出厂 L1+L2，L2 配应用内授权向导

「无 Root」承诺分三级：**L1 安装即用**（仅软件虚拟化，全 arm64 设备兜底）、**L2 一次开发级授权**（adb pm grant / Shizuku，解锁 AVF/pKVM 硬件虚拟化）、**L3 OEM/系统级**（仅路线图愿景，产品内不做承诺）。MVP 同时出厂 L1+L2：L2 由应用内授权向导承载——**先能力检测**（feature flag、权限状态、custom VM 能力谱），通过才展示引导；Shizuku 优先、ADB 命令兜底（逐字可复制 + 图文步骤）；检测不支持的设备**根本不展示** L2 引导，避免无效折腾。目标用户定位为技术早期采用者；MVP 不按大众产品的增长叙事规划。

## Considered Options

- **MVP 只做 L1（否决）**：near-native 体验到达过晚；且 AVF 已是 Full Linux 契约下的执行策略（ADR-0002），延后交付只是把同一工作量推后并让向导 UX 变成补丁。
- **MVP 只做 L2（否决）**：失去全设备兜底，产品叙事从第一天变窄；L1 是"无 Root"承诺的底线保障。

## Consequences

- 文案永不承诺"所有设备都能硬件加速"；L1/L2 体验落差由常驻徽章 + 设置页常驻的"提升到硬件加速"入口管理。
- 渠道策略（Play 上架意义存疑）推至发布渠道决策，但本题选择使其偏向 GitHub Releases / F-Droid。
- per-OEM 授权引导文案依赖研究票「国产 OEM AVF 与 ADB 授权现状」的数据。
- 原型票「AVF 端到端验证（真机）」成为 L2 信心与排期的实测闸门；用户是否持有 AVF 设备待确认（不影响本决策）。
