# 存储模型：raw 稀疏单根盘 + SAF 导出备份

Full Linux 实例持久层契约五条：

1. **格式：raw 稀疏文件**（两执行策略同格式；内部文件系统 provisioning 时格式化为 ext4）。
2. **实例盘组织：单根盘**——发行版 rootfs 装配进根盘后，系统升级就是 guest 内的 apt/apk upgrade；不分系统层/数据层，App 升级永不触碰实例内容。
3. **扩容进 MVP**（默认容量创建时按预算建议；扩容 = 扩镜像文件 + guest 内在线扩文件系统，通道依赖桥接票）。
4. **快照不进 MVP**（明确非目标）；**备份/导出进 MVP**——经 SAF 单向导出根镜像 + 实例元数据到用户选定位置，导入恢复为后续。
5. **位置：全部 App 私有存储**（每实例独立子目录）；镜像不进共享存储；**明确排除 Android 自动备份覆盖镜像目录**。

## Considered Options

- **qcow2 进 MVP（否决）**：AVF/crosvm 支持不确定 + "实例在策略间互换"要求两策略同格式；raw→qcow2 有标准无损转换工具，后路保留。
- **系统层/数据层分层（Podroid 模式，否决）**：其分层源于"OS 随 App 更新分发"（只读 squashfs + 迁移脚本）；我们的 OS 来自官方 tarball、归用户所有、在 guest 内升级——分层数据模型多余。
- **镜像放共享存储（否决）**：污染 ADR-0001 的安全边界与类别人设。

## Consequences

- **FUSE 之下私有目录的随机写性能是最大未知数**，为「QEMU TCG 实机基线」原型必测项；数据若糟糕，本题的格式/位置选型重开（标记为待原型，不视为已证实）。
- 稀疏文件的 ENOSPC 行为必须优雅：创建前空间预检 + 运行时告警。
- "无快照"如实告知用户（UI/文档不得暗示）；升级失败的恢复路径 = 导出备份或重建。
- 大镜像导出的耗时预期管理属实现期事项。
- 若未来切 qcow2，有 qemu-img 类工具做一次性迁移，成本可控。
