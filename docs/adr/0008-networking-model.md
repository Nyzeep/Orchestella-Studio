# 网络模型：默认出站 NAT + 显式端口转发（默认仅本机）

产品网络语义四条，两执行策略机制各异、语义一致：

1. **出站默认允许，走 NAT**：guest 可直接访问外网，无需配置，对外不可见——"装完就能 `apt update`"的底线体验。
2. **入站只经显式端口转发规则**：规则模型 `{协议, 宿主端口, guest 端口, 绑定范围}`；**绑定范围默认 127.0.0.1**，LAN 暴露（0.0.0.0）必须显式选择并给出安全提示；规则持久化、支持运行时热更。
3. **机制/语义分离**：QEMU 档 SLIRP hostfwd、AVF 档 vsock 转发隧道（Podroid 双路径实证可行）；上层只见转发规则（ADR-0002 的网络域具体化）。DNS 属策略内部机制，契约只承诺"guest 有可用解析"。
4. **非目标（诚实标注）**：IPv6 不承诺；VPN 共存不承诺、标注"未验证"并列入原型观测项；host mode（guest 获得局域网身份）不进 MVP，列为未来增强。

## Considered Options

- **默认绑定 0.0.0.0（否决）**：把 LAN 暴露设为默认 = 攻击面默认最大化；收紧→放开容易、放开→收紧要迁移存量规则与习惯，安全默认值必须一次做对。
- **VpnService/TUN 方案（否决出 MVP）**：与真实 VPN 互斥（单 TUN 限制），语义反而更窄；SLIRP/TAP 路径已足够并已被实证。
- **IPv6 进 MVP（否决）**：SLIRP 关闭 IPv6 是成熟做法；承诺没验证的东西违背"可测量承诺"原则。

## Consequences

- SLIRP 吞吐上限叠加 TCG 减速：软件虚拟化档的网络预期要压低；passt 类增强进雾区跟踪。
- 转发热更的两策略机制差异（QMP 动态 hostfwd vs vsock 控制命令）由桥接协议票统一命令集。
- 后台网络可用性受生命周期票约束（宿主端监听活在 App/VMM 进程内）。
- AVF 档网络对第三方 custom VM 的实际行为待原型实测；若受限，能力矩阵如实降级。
- 契约测试必须覆盖：转发规则在两策略下的语义等价性。

## Amendments & Errata (2026-10-01 修订与勘误)

1. **Ticket 26 验收事实固化**：
   - 纯软模拟档（QEMU TCG）基于 SLIRP 的用户态出站 NAT 网络已在 HONOR 80 GT 真机通过端到端验收；Alpine 3.24.1 实例完成 `apk update` 及网络通信，网络契约第一条在 L1 档位完全闭环。
   - 转发规则热更已通过双抽象套接字中的 `droidlayer-qmp` 通道实现（执行 `hostfwd_add` / `hostfwd_remove` QMP 命令），避免了重启 VMM 进程。
2. **2026 最新网络态势与架构升级**：
   - **AVF 档 vsock 转发隧道与 virtio-net 对齐**：在 AVF 硬件加速模式下，结合 AOSP Linux Terminal 的架构演进，虚拟机网络将通过 vsock 转发代理与宿主网络栈桥接；如果设备具备 TAP 权限（如通过 Shizuku 授权的特权网络组件），可自适应升级为高性能 virtio-net 桥接；
   - **局域网调试模式与安全边界**：为支持 Phase 4 容器与 Web 开发工作流（如 Vite/FastAPI 调试），显式端口转发允许用户一键开启临时局域网暴露（绑定 `0.0.0.0`），但必须遵循 ADR-0010 施加显著的前台 UI 告警及自动超时关闭机制；
   - **IPv6 依然作为非目标**：2026 年移动网络环境下移动端虚拟机 IPv6 SLA 依然高度碎片化，维持“MVP 及近期演化中不承诺 IPv6”的审慎决策。
