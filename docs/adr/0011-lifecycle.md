# 生命周期：前台可靠、后台尽力而为、实例持久化 + 冷恢复

1. **前台使用：完全可靠**（承诺基线）。
2. **后台运行：尽力而为**——前台服务（specialUse）+ 唤醒锁；提供"忽略电池优化"引导；不承诺后台无限长跑，OEM 查杀风险如实告知。
3. **App 进程死亡：VM 随之停止**（v1 不承诺 VM 独立存活）；**实例状态持久化从第一天存在**——重启 App 后同一实例一键**冷恢复**（重建运行环境，非内存态恢复）。"VM 死了"与"我的 Ubuntu 没了"是两件事，产品只承诺后者不发生。
4. **异常与重启**：VMM 异常退出 → 实例标记"异常终止"，提供清理/日志导出路径；设备重启默认不自启实例，可选"开机自启"设置。
5. **电池策略：两档可选**（性能/均衡）+ 常驻运行状态通知；锁屏默认继续运行（服务器场景底线）。
6. **phantom process killer 应对**：宿主侧进程模型刻意收敛（重活全在 guest 内）；文档指引 Android 14+ 官方关闭开关但不作为功能前提。
7. **热恢复（内存态 pause/resume）不进 MVP**——两策略支持度均未验证，进雾区等原型数据。

## Considered Options

- **承诺后台无限长跑（否决）**：与 Android 机制及 OEM 现实对抗，承诺即违约。
- **v1 探索 VM 独立存活（AVF 路径可能允许，推迟）**：依赖未实测的 AVF 行为；若原型证实，作为能力矩阵增强后补，v1 统一按 QEMU 档（较弱）语义设计 UX。
- **热恢复进 MVP（否决）**：QEMU savevm / AVF 对应机制支持度未知；冷恢复以极低成本覆盖绝大多数场景。

## Consequences

- 实例元数据携带生命周期状态字段（运行中/已停止/异常终止…），跨进程死亡持久——v1 必须做对。
- "后台可达性"（网络票遗留）由本票答案收敛：转发监听随进程死亡失效，属"尽力而为"档。
- specialUse FGS 的政策敏感性联动发布渠道决策（Play vs GitHub/F-Droid）。
- 文案纪律：永不承诺"24 小时无人值守稳定运行"（与 ADR-0010 只加码原则同构）。
