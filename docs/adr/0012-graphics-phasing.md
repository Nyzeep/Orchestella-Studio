# 图形路线分期：MVP 终端 only，四里程碑渐进

1. **M1（MVP）：终端 only**——连 VNC 都不做。验收：创建→引导→shell 流畅、出站网络、转发规则、只读共享。文案定位"Linux 终端与服务器环境"，不做桌面营销。
2. **M2：VNC 软渲染通道**——guest 内 X server + 宿主自研 RFB 客户端 + **完整输入集成（触摸→鼠标、软键盘、IME 桥接）**；作为"显示通道"增强能力加入暴露面白名单（ADR-0010 流程）。验收示例：Debian 中启动轻量桌面并流畅操作浏览器。
3. **M3：Wayland 原生通道评估**——仅当 M2 出现结构性瓶颈（延迟/分辨率切换/多屏）才投入。
4. **M4：GPU 加速（virtio-gpu/gfxstream）**——前置条件：原型证实第三方 App VM 的 gfxstream 可用性 + 软件虚拟化档 virtio-gpu 2D 可行性；原型否决则改道 2D 或优化软件渲染。验收：对比 M2 的帧率基准显著提升。

架构留位：MVP 的桥接协议与能力矩阵**不预设图形**，但预留"显示通道"增强类型——M1 不为图形付任何架构成本。

## Considered Options

- **MVP 含最简 VNC（否决）**：输入/IME 集成是隐藏的半壁江山（中文输入法桥接、物理键盘、触控映射），会把 MVP 拖大半个身位且质量难保证。
- **MVP 直接承诺桌面（否决）**：范围失控的第一大源；质量不达标的图形会定死早期口碑且砍不掉——不做是可逆性最高的选择。

## Consequences

- "没有 GUI"的桌面期望用户会流失，用产品定位文案对冲（目标用户=技术早期采用者，ADR-0003）。
- 竞品（Podroid 等）已有桌面演示：差异化叙事放在平台正确性（契约/安全/供应链）而非功能清单。
- TCG 档图形体验 = 软渲染 + 5–20× CPU 减速叠加，M2 发布时性能预期管理必须到位。
- M4 若 gfxstream 被原型否决，硬件虚拟化档之外的 GPU 加速可能长期缺位——文案不许许诺。
- M2 工作量预算按"图形一半、输入/IME 一半"的现实排。
