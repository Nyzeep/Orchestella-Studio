# USB/音频范围：MVP 均不做，分别挂 M2+ 与 M2

1. **USB 直通：不进 MVP**。挂 M2+ 档，**QEMU 档先行**（UsbManager fd 直通模式自研实现）；AVF 档直通能力待原型证据、可能长期缺位（如实标注能力矩阵）。每设备运行时授权弹窗 + 暴露面白名单修订流程（ADR-0010）；摄像头等特殊类别明确不承诺。
2. **音频：不进 MVP**。挂 M2（与图形同期），方向仅 guest→host 输出（已验证模式自研实现）；麦克风方向"可能永不"（RECORD_AUDIO 隐私权限 + 用例弱），除非真实需求推动。
3. **产品文案用路线图语言**（"USB 直通与音频在路线图"），不用"不支持"语言。

## Considered Options

- **USB 提前进 MVP（否决）**：权限迂回 + 安全暴露面（白名单第一版就要背设备直通）+ 适配器兼容性长尾三重成本，且 AVF 档无解。
- **音频提前进 MVP（否决）**：终端场景无消费方；音频的价值寄生于图形（M2），提前做等于为不存在的场景付维护成本。

## Consequences

- USB 需求用户（串口/YubiKey/U 盘场景）在 MVP 阶段流失，靠路线图标注对冲。
- 能力矩阵如实标注：USB 直通 = 仅软件虚拟化档（延后可能也仅此档）。
- 音频实现期需处理音频焦点管理（与生命周期交互），M2 期事项。
- 里程碑可互换：若 M1 期间 USB 需求强烈（串口人群），USB/音频在 M2 内互换成本为零。
