# 主机数据出站与内容边界硬约束

> 状态：项目级 active policy ｜ 版本：1.0 ｜ 适用：所有 DroidLayer Agent、App host 代码、
> 构建脚本、CI、运行时数据路径和以后新增的远程能力

## 1. 默认拒绝主机侧数据出站

DroidLayer 当前不提供云备份、仓库同步、整仓索引或后台 workspace snapshot。任何代码、脚本、
CI job、依赖或 Agent 行为都不得在没有用户可见触发和批准的情况下：

- 递归枚举工作树、`.git` 或外部项目目录；
- 生成 baseline、checkpoint、manifest、索引或等价的全量/增量内容集合；
- 对主机侧内容做归档、压缩、加密、哈希、缓存、排队、断点续传或自动重试后外发；
- 通过服务端下发的 token、公钥、对象存储表单或动态 endpoint 自行获得外发授权。

加密只改变传输和存储形态，不改变内容分类，也不等于用户拥有解密权或完成了知情授权。

## 2. 新远程能力的必要条件

若未来产品确需增加主机侧远程能力，必须先完成产品/架构决策并在实现前固化以下内容：

1. 用户可见的主动触发、可取消动作和默认关闭状态；
2. 精确的数据范围、文件数量/字节数、排除项、用途、保留期和删除语义；
3. 固定或可审计的 destination allowlist、TLS 身份校验与协议记录；
4. 本地拒绝门：用户配置、策略或端点不可确认时不发请求；服务端响应不能绕过本地拒绝；
5. 失败即停：网络失败不得静默建立 pending 队列、无限重试或重新扫描完整工作区；
6. 脱敏日志、审计事件、单测/集成负例和独立 review；
7. 对应 ADR、spec、ticket acceptance criteria 和隐私说明的变更记录。

没有同时满足这些条件时，正确行为是拒绝该能力并升级，而不是先实现上传再补开关。

## 3. 永不默认纳入的内容

以下内容在任何后台、隐式或“为了方便诊断”的传输中都必须排除：

- `.git/objects`、`.git/lfs`、`.git/logs`、reflog、refs、`.git/config` 和全部历史；
- `.env`、API key、token、密码、私钥、签名材料、provider 配置和 credential cache；
- workspace 外部路径、内部 Git host、未公开分支名、构建日志和包含用户代码的 crash dump；
- `guest` 根盘、快照、实例数据或外部 artifact，除非已有明确产品决策和用户主动 Export
  范围；当前 ADR-0007 的 Export 是经 SAF 的本地单向备份，不是云同步。

即使用户主动创建 Export，也必须先展示范围并默认排除 Git 历史、凭据和无关目录；实现不得
把“文件名过滤”当作历史对象过滤的替代品。

## 4. 允许的网络行为不扩大主机数据权限

下列行为不构成主机侧数据外发授权：

- 用户在 Full Linux Runtime 内主动使用的 guest 出站 NAT（ADR-0008）；
- 按 `DistroManifest` 指定 URL 下载发行版输入，并在装配前做完整大小与 SHA-256 校验；
- 用户开启的 GitHub 更新检查（ADR-0015），且只发送完成该检查所需的最小版本信息；
- CI 获取已锁定、已认证、可复现的源码和构建输入。

这些行为仍必须限制端点、输入、日志和重试范围；它们不能读取宿主工作树来“丰富上下文”，
也不能转化为向第三方对象存储上传用户代码的通道。任何动态 URL、服务器下发凭证或 direct-to-
object-storage 设计都必须先通过第 2 节的本地授权门。

## 5. Agent 与工具的内容边界

- Agent 默认只在当前本地工作区和用户明确指定的 approved resource root 内工作；不得把源代码、
  Git 历史、凭据、完整日志或大段用户数据粘贴到外部 Agent、云任务、第三方代码分析服务、
  issue 评论或无关附件。
- 需要请外部资料时只传脱敏问题和最小片段；若无法脱敏，停止并请求用户明确授权。
- `git diff`、终端输出、截图和报告在呈现前必须检查 token、私钥、`.env`、内部 host、用户
  路径和完整文件清单；报告只保留验证所需的摘要、hash 或稳定别名。
- 任何“仅发送 manifest/telemetry/diagnostic”的说法都要按真实字段检查；文件名、路径、
  Git ref 和 hash 也属于可能敏感的主机侧元数据。

## 6. 代码与 CI 的失败即停门

新增或修改涉及文件系统、网络、归档、实例导出或诊断的模块时，必须提供可执行的负例，至少
覆盖：

- 配置关闭时没有请求、没有队列、没有重试；
- 未知 endpoint、动态凭证、超范围路径或不完整清单被拒绝；
- 含 `.git`、`.env`、reflog、LFS 和内部 URL 的 sentinel fixture 不会进入主机侧传输；
- 传输失败不会在后台重新打包或继续发送；
- 日志和报告不包含原始内容或秘密。

测试 fixture 必须是合成数据，不能把真实仓库历史或真实凭据带入测试。CI 失败时停止在 gate，
不得以 `continue-on-error`、条件跳过、旧 artifact 或“只做静态检查”冒充安全通过。

## 7. 冲突处理

若实现需求与本策略冲突，Worker 必须停止相关实现，保存最小脱敏证据，并按
`ARCHITECTURE_CHANGE_POLICY.md` 升级。任何单一 ticket、服务器默认值、模型建议或“为了体验”
都不能单独修改本策略。
