# 疑似越界外发事件响应与凭据轮换硬约束

> 状态：项目级 active policy ｜ 版本：1.0 ｜ 适用：发现未知读取、后台归档、异常出站、秘密
> 泄露或第三方工具行为与声明不一致时

本文件处理的是 DroidLayer 工程和交付链路中的疑似事件。它不要求重新验证用户已明确说明
已经删除的其他工具资料；当用户给出现成事件结论时，后续工作直接按“内容可能已外泄”处理。

## 触发条件

出现以下任一迹象就进入事件流程，不等待完整归因：未知 destination、未声明的 workspace 扫描、
整仓/`.git` 归档、失败后自动重打包、日志出现用户代码或 secret、服务端开关改变本地数据流，
或工具的隐私开关与真实 I/O 不一致。

## 固定顺序

### 1. 先停止新增外发

停止受影响的进程、任务、CI job 或 feature；在可控的本地层禁用相关网络路径或让策略返回
拒绝。不要通过反复运行来确认，不要先清空队列、删除日志、重写 Git 历史或卸载工具，以免
破坏最小证据。若停止动作本身会覆盖证据，先记录时间、命令和影响。

### 2. 保全元数据，不复制敏感载荷

在 approved external resource root 保存脱敏的时间线、进程/endpoint、文件大小、manifest 摘要、
hash、失败计数和配置状态；记录哪些事实已确认、哪些只是推断。不要复制密文、整仓、`.git`、
私钥或真实凭据到报告、附件或外部 Agent。原始日志如必须保留，按 `HOST_ENVIRONMENT_POLICY.md`
披露路径、owner、保留期和清理责任，并限制读取权限。

### 3. 把出现过的凭据视为已泄露

按影响范围立即轮换或撤销：API key、数据库密码、CI token、部署 key、Git credential、签名
材料和写入过 Git 历史的旧 secret。只删除工作树文件、只删除 pending 包或只修改最新提交
不构成修复；Git 历史、reflog、LFS 和缓存中的旧值必须分别评估。轮换顺序、完成时间和未完成
项写入脱敏事件报告，不把新凭据写入报告或日志。

### 4. 评估范围与通知

至少核对以下范围：当前工作树、Git 历史/refs/reflog/LFS、实例根盘、构建/CI artifact、配置
文件、发送端点、重试窗口、接收方和可能的保留期。若无法证明未外发，使用“可能已外泄”措辞，
不要用本地密文不可解、上传失败或 UI 开关状态推断云端没有副本。需要通知的仓库所有者、凭据
所有者或用户由 Orchestrator 根据事件范围协调；通知内容只包含必要的脱敏事实。

### 5. 修复与放行条件

受影响能力在以下项目完成前保持冻结或不可发布：

- 本地默认拒绝与可见关闭门已存在，并且服务端响应不能绕过；
- 明确数据范围、端点 allowlist、取消、失败和重试语义；
- 针对 `.git`、secret、全量扫描、重打包和日志泄漏的负例测试通过；
- 运行时、构建链和交付 artifact 的独立 review 完成；
- 事件报告、凭据轮换和残余风险由用户/维护者确认。

修复不能通过静默缩小报告范围、改写失败历史、删除审计记录或把功能移到另一个后台线程来
完成。若修复需要改变 accepted ADR、spec、Full Linux 契约或暴露面白名单，必须先走架构变更门。

## 事件报告最低字段

正式报告放在 `docs/reports/orchestration/`，敏感原始证据留在 approved external resource root。
报告必须包含：触发时间、scope、影响分类、已确认事实、未确认假设、停止动作、证据路径与 hash、
凭据轮换状态、修复提交/测试、未清理残留、放行人和是否触发 Architecture Change Policy。报告
不得包含秘密、完整 Git 路径清单、原始用户代码或可复用 token。
