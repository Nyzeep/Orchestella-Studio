# 防御性硬约束目录

> 状态：项目级 active policy ｜ 版本：1.1 ｜ 生效日期：2026-09-19（v1.1 修订生效：2026-09-28，经用户授权）

本目录是 DroidLayer 后续所有 Agent Session 的安全与数据边界硬约束入口。它吸收了本次
用户提供的“AI 编程工具静默收集整仓与 Git 历史”威胁模型，但不把文章中的个案重新当作
DroidLayer 的取证结论；本目录只定义 DroidLayer 以后必须遵守的工程行为。

## 强制读取与优先级

在任何后续任务执行第一条任务性命令、读取任务范围外文件、运行构建/测试、创建产物或
访问网络之前，Orchestrator、Worker、Child、review 和 research session 必须阅读本文件
以及本目录内全部 policy 文件：

- `DATA_EGRESS_AND_CONTENT_BOUNDARY_POLICY.md`
- `INCIDENT_RESPONSE_AND_CREDENTIAL_ROTATION.md`

这些文件是硬约束，不是建议、提示语或验收完成后的可选清单。若实现、工具、第三方服务、
服务器返回值或现有文档与其冲突，必须停在冲突处、保留最小证据并升级；不得用“加密了”、
“失败会重试”或“这是开发工具默认行为”替代用户授权。

## 稳定性与变更门

本目录按安全策略维护，禁止按单个 ticket 临时放宽、复制出第二份或用报告中的例外覆盖。
只有在有明确用户授权的安全优化方案时，才能修改这里的文档；方案必须说明威胁模型、受
影响的规则、迁移与回滚、负例测试、审查人和生效范围，并按
`docs/agent-handoff/ARCHITECTURE_CHANGE_POLICY.md` 检查是否触及 ADR、spec 或产品契约。

## 适用范围

“主机侧内容”包括仓库工作树、`.git`、ignored 文件、构建/日志/报告、外部 artifact 根、
实例元数据以及 Agent 读到的用户代码和凭据。它不因被压缩、加密、哈希、放入快照或上传
到对象存储而改变数据分类。

已批准的 guest 出站 NAT 仍属于 ADR-0008 的产品能力；它是用户在 guest 内发起的网络行为，
不等于允许宿主 App 或 Agent 静默读取、打包或外发宿主工作树。任何新的 guest→宿主能力仍
受 ADR-0010 的暴露面白名单约束。

## 每个任务的最小安全门

1. 先写出本次任务会读取的路径、会产生的输出、会访问的网络端点和数据分类。
2. 对主机侧内容执行默认拒绝：没有明确的用户可见动作、范围、端点和测试，就不读取、不
   枚举、不归档、不上传、不建立后台队列。
3. 运行命令前确认输出路径符合 `ARTIFACT_ORGANIZATION_POLICY.md` 和
   `HOST_ENVIRONMENT_POLICY.md`；敏感内容只保留脱敏摘要。
4. 对任何新的 I/O 或传输路径补充失败即停的负例测试，并在报告中逐项区分已验证、未运行
   和待用户操作。
5. 发现疑似越界外发时，立即转入 `INCIDENT_RESPONSE_AND_CREDENTIAL_ROTATION.md`，不继续
   通过重复运行来“确认”。

## 证据文件命名与保全纪律

> 状态：本目录硬约束 ｜ 生效日期：2026-09-28（用户授权）｜ 适用：所有 Agent 会话，即刻生效

### 威胁模型

宿主侧清理/维护工具会按文件扩展名批量清理目标（2026-09-28 用户确认：清理工具按扩展名
一次性误删了项目证据文件）。任何以扩展名区分证据的批量清理都可能再次命中证据文件，
且清理动作不区分“项目证据”与“可清理产物”。

### 规则

- 所有 Orchestrator、Worker、Child、review、research 会话的**原始执行/验证证据**——
  命令输出、验证记录、探针/复现记录——**不得使用 `.log` 扩展名**；使用 `.md`、
  `.log.txt`、`.json`、`.tsv` 等不受常见清理规则影响的扩展名。
- 证据必须存放于**专门、目录结构清晰**的位置（按批次/用途组织），不得散落在工具目录、
  源码树或临时目录。
- 每一步证据生成后**即时复制**到保全位置，不依赖单一副本。

### 迁移与回滚

- 既有历史 `.log` 文件**原样保留**：不重命名、不删除、不移动；仅允许**追加只读孪生**
  （字节一致的 `.log.txt` 等副本）。
- 回滚 = 将本 README 恢复为变更前字节（变更前/后 hash 登记于变更批次的证据目录）。

### 负例测试

各会话批末门必须包含“新建 `.log` 扩展名证据”检测：批内新出现 `.log` 文件即判失败
（各批次 gate 携带等价的定点检查；本修订批次提供可复用参考实现）。

### 审查人

独立 reviewer 在正式复评中核验本节与各批负例测试的执行记录。

### 架构变更检查结论

按 `ARCHITECTURE_CHANGE_POLICY.md` 检查：本变更仅涉及工程纪律与文档，不触及任何
ADR、spec、产品契约或暴露面白名单，不触发架构变更流程。用户授权日期：2026-09-28
（用户裁定：删除者身份/已停用确认 + 缓解措施升级为硬约束，见同一日期的
证据日志丢失事件放行与闭门附录）。
