# 应用图标资产

Orchestella 的启动器图标（自适应图标 + 传统 48dp 图标）与商店/文档用静图，全部由
`tools/branding/make_app_icons.py` 从一张源美术生成，不依赖网络、不依赖 numpy，
只有 Pillow。

## 源美术

| 项目 | 值 |
| --- | --- |
| 文件 | `source-mascot.jpg`（源图副本，1920×1920 JPEG） |
| 主体 | 紫色头发看板娘/吉祥物头像，脸部朝向左下，主体在左侧与下侧越出画布 |
| 背景色 | `#242424` (36, 36, 36) 纯色 |
| 身体紫 | `#41375A` (65, 55, 90) |
| 脸部奶白 | `#FDF1DB` (253, 241, 219) |
| 几何描边 | 淡紫细线 ≈ (150, 135, 168)，宽约 10–12 px |
| 脸部包围盒 | x 86–1381 / y 607–1754（1920 坐标，含奶白三角耳） |

## 重要发现：眼睛是背景色

源图里眼睛不是墨色，而是**和背景完全相同的 `#242424`**（原画就是把眼睛"挖空"）。
因此不能用"颜色接近背景色就判为背景"的全局阈值去抠——那会把眼睛一起挖成洞，
预览时看起来就是两道会透出白底的空缝。

`make_app_icons.py` 的做法：

1. **四边向内 flood fill**：种子只取"位于图像最外两圈、且颜色已经接近背景"的像素。
   源图本身是裁切图（主体压到左/下边缘），盲目用四个角做种子会把整个身体吃掉。
2. **封闭区域逐个分类**：flood 到不了的封闭区域包括身体、三角内部、眼睛。对每个
   区域取一圈**避开自身抗锯齿边缘**（半径 5–6 px）的环，看环的平均色：
   - 淡紫细线（亮度高、非奶白）→ 三角内部 → 挖成透明；
   - 奶白（脸部）→ 眼睛 → 保留为不透明；
   - 其它（紫色/暗部）→ 一律保留，不做"盲挖"。
3. **边缘去污**：只对朝向透明背景的那一圈像素，用相邻内部色覆盖，避免抗锯齿边在
   深色底上看起来像一圈灰/黑描边；随后加 1 px 向外 37% alpha 羽化。

## 构图语义

所有尺寸共用同一套语义：**等比缩放 + 居中裁切（cover），锚定脸部中心，绝不非等比拉伸**。
裁切框边长由脸部包围盒高度决定（`FACE_HEIGHT_RATIO = 0.54`，即脸高约占画布 54%），
中心取脸部包围盒中心。

| 用途 | 视野 | 说明 |
| --- | --- | --- |
| 自适应前景 / 单色层 | 108dp 整张画布 | 脸在 108dp 上占 x 21.1–86.9dp、y 24.8–83.2dp；72dp 可见区内完整 |
| 传统方形/圆形图标、商店静图 | 74dp 窗口 | 即"把自适应图标的 72dp 可见区放大填满图标"；74dp 保证裁切框完全落在源图内（左边余 5.8 px、下边余 11.8 px），因此不需要延展像素、也不会出现暗色沟槽 |

安全区实测：脸部包围盒有 **85.1%** 的面积落在中心 66dp 安全圆内。
按 72dp 圆形遮罩预演：主体被裁掉 **25.2%**（主要是四角的紫色块与三角装饰），
奶白脸部/耳朵只被裁掉 **3.75%**（极限位置的耳尖），脸本身完整。

## 色值

- `ic_launcher_background = #FF242424`（`app/src/main/res/values/colors.xml`），
  与源图背景一致，所以前景的透明区域和背景层叠合后无接缝。

## 重新生成

```bash
python tools/branding/make_app_icons.py
# 换源图（会把新图复制成 source-mascot.jpg 再基于它生成）
python tools/branding/make_app_icons.py --import-source <新图.jpg>
```

脚本会重写全部 PNG 与 `mipmap-anydpi-v26/ic_launcher*.xml`，并在结束时断言：
尺寸正确、前景四角 alpha=0、单色层只有纯黑与透明、512 商店图不含 alpha 通道。
`app/src/main/AndroidManifest.xml` 与 `colors.xml` 由人工维护，脚本不改。

自适应图标（108dp 画布）：

| 密度 | 前景 | 单色 | 传统方形 (48dp) | 传统圆形 (48dp) |
| --- | --- | --- | --- | --- |
| mdpi | 108 px | 108 px | 48 px | 48 px |
| hdpi | 162 px | 162 px | 72 px | 72 px |
| xhdpi | 216 px | 216 px | 96 px | 96 px |
| xxhdpi | 324 px | 324 px | 144 px | 144 px |
| xxxhdpi | 432 px | 432 px | 192 px | 192 px |

- `app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml`、`ic_launcher_round.xml`：
  `<adaptive-icon>`，background 用颜色资源，foreground / monochrome 用位图。
- `app/src/main/res/mipmap-*/ic_launcher_foreground.png`：108dp 透明底主体。
- `app/src/main/res/mipmap-*/ic_launcher_monochrome.png`：纯黑不透明剪影 + 透明底，
  由系统自行染色。剪影取"开运算后的主体 + 保留眼睛镂空"：眼睛镂空让染色后仍能认出
  是脸；与主体相连的细几何线无法在不钝化发梢的前提下去掉（要 8px 以上的开运算），
  因此保留为极细线条（xxxhdpi 约 2.7 px、48dp 下约 0.3dp，等于看不见）。
- `app/src/main/res/mipmap-*/ic_launcher.png`：含背景的完整方形图（API 26 以下）。
- `app/src/main/res/mipmap-*/ic_launcher_round.png`：同尺寸圆形遮罩版，四角透明。

本目录（`docs/assets/branding/`）：

| 文件 | 规格 | 用途 |
| --- | --- | --- |
| `app-icon-512.png` | 512×512，不透明、无圆角、满幅 | Play Store 图标 |
| `app-icon-1024.png` | 1024×1024，不透明、满幅 | README / 社交分享 |

这些位图默认会被仓库根 `.gitignore` 的 `*.png` / `*.jpg` 和 `/docs/` 规则挡住，
`.gitignore` 末尾有专门的例外块放开本目录，以及 `app/src/main/res/mipmap-*/ic_launcher*.png`。

## 已知取舍

- 源图在左侧与下侧本身就是裁切图，方形图标采用 74dp 窗口正是为了让这两条裁切线落在
  图标边缘之外；如果以后把 `LEGACY_VIEW_DP` 调大（视野更宽），脚本会直接断言失败，
  而不是偷偷延展像素。
- 同理，1024 px 静图也做满幅而不是"居中留白"：只要采用比 74dp 更宽的视野（比如完整
  108dp 画布），源图的裁切线就会变成画面内部一条笔直的紫色边界，看起来像贴图出错。
- 三角装饰线在 108dp 画布上很细（xxxhdpi 约 2.7 px、mdpi 约 0.7 px），既不会被遮罩
  完全吃掉，也不会在 48dp 下变成噪点；但极端缩放下会自然消失。单色层保留了与主体相连
  的这几根线（见上），如果将来要求纯剪影，可以调大 `MONO_OPEN_PX`，代价是发梢变钝。
- 前景 PNG 的透明区保留的是背景色像素（alpha=0），这样缩放重采样时边缘不会拉出黑边；
  它只适合叠在 `#242424` 背景上使用，不要把它当"白底可直接用"的通用素材。
