# 01: 实例快速向导与虚拟磁盘网络配置

**What to build:**  
在 Orchestella Studio 中构建对标 VMware Workstation 的工业级「实例快速创建向导（Instance Creation Wizard）」。替代现有一键直接下载创建的粗糙模式，引导用户分步完成：虚拟磁盘大小及宿主挂载目录指定、网络环境自检与镜像软件源下拉预设、初次启动自动执行系统更新选择（后台根据发行版自动判断执行 `apt update && apt upgrade` / `apk update && apk upgrade` 等）、以及 CPU 核心数与内存的手动分配。

**Blocked by:** None (可立即启动)

**Status:** ready-for-agent

---

## 需求背景与痛点

1. **现有创建流程过于单一粗放**：当前创建 Debian/Alpine 实例仅能一键分配写死的 2GB/10GB 磁盘和推荐内存，用户无法自由指定磁盘容量、无法配置挂载目录，更无法在创建期配置网络镜像源；
2. **移动网络依赖与更新阻断**：国内移动网络环境下，默认官方海外源下载慢、解析超时。用户进入终端后需手动修改复杂的 `/etc/apt/sources.list` 或 `/etc/apk/repositories`，体验极差；
3. **初次启动环境陈旧**：很多 Linux 镜像打包时间较早，进入后直接安装软件常因索引未更新报错。用户希望在向导中勾选“创建后自动更新软件”，由系统在后台全自动先行同步最新软件索引并升级核心包。

---

## 详细功能规格与交互设计

### 1. 引导层交互流程（Wizard Flow）
参考 VMware Workstation "New Virtual Machine Wizard" 经典体验，设计清晰的步骤卡片或选项卡：

```mermaid
flowchart LR
    A["步骤 1: 磁盘与存储"] --> B["步骤 2: 网络与镜像源"]
    B --> C["步骤 3: 硬件配额分配"]
    C --> D["步骤 4: 启动任务配置"]
```

#### 步骤 1：虚拟磁盘与挂载点配置
- **磁盘容量**：预置快捷胶囊（`4 GB`、`8 GB`、`16 GB`、`32 GB`）及自定义输入框；根据宿主当前内部存储剩余空间（`StatFs`）进行预检，预留至少 2GB 宿主缓冲；
- **磁盘类型**：默认支持稀疏镜像（Sparse Raw Volume），按需占用物理存储；
- **挂载点与外部共享目录**：支持用户勾选“挂载宿主共享目录（Host Shared Directory）”，通过 SAF 目录选择器选取外部 `Documents` 或 `Downloads` 文件夹，自动映射为 Guest 内的 `/mnt/shared`。

#### 步骤 2：网络配置与镜像源下拉选择
- **网络诊断看板**：
  - 显示宿主当前网络模式（Wi-Fi / 移动蜂窝网络 / 离线）；
  - 显示检测到的宿主 IP、默认网关与 DNS 服务器；
  - 提供「测试网络连通性」轻量按钮（Ping/HTTP HEAD 探测）。
- **镜像软件源下拉框（Mirror Selector）**：
  - 提供标准下拉列表：
    - `官方默认源 (Official Upstream)`
    - `清华大学开源软件镜像站 (Tsinghua TUNA - 推荐国内极速)`
    - `中国科学技术大学镜像站 (USTC)`
    - `阿里云开源镜像站 (Aliyun Public)`
  - 后台模型维护各发行版源配置模板（如 Debian/Ubuntu 生成 `sources.list`，Alpine 生成 `repositories`，Arch 生成 `mirrorlist`），在 rootfs 挂载解包时无损覆写对应配置文件。

#### 步骤 3：硬件参数分配（保留原有动态滑块）
- **vCPU 核心数分配**：滑块与步进按钮（1 ~ 宿主总核心数），默认设定为宿主核心数的 50%（不超过 4 核）；
- **RAM 内存分配**：提供安全区间滑块（512 MB ~ 宿主总内存 - 2GB 保留区），实时呈现红/黄/绿安全色阶，防止 OOM 导致宿主杀进程；
- **说明**：该步骤设置的硬件参数作为该实例的初始规格，创建完成后仍可在二级详情页使用已有的动态硬件编辑器随时升降配。

#### 步骤 4：初次引导自动化软件更新选项
- **UI 交互**：提供显眼的勾选开关：「🚀 实例初次引导时自动执行系统软件更新」；
- **后台命令智能匹配矩阵**：
  | 目标发行版 | 智能匹配并执行的更新命令 | 守护与超时策略 |
  | :--- | :--- | :--- |
  | **Debian / Ubuntu / Kali** | `DEBIAN_FRONTEND=noninteractive apt-get update && apt-get upgrade -y` | 附带 300s 超时守卫 |
  | **Alpine Linux** | `apk update && apk upgrade` | 附带 120s 超时守卫 |
  | **Arch Linux** | `pacman -Sy --noconfirm && pacman -Su --noconfirm` | 附带 300s 超时守卫 |
  | **Fedora** | `dnf upgrade -y --refresh` | 附带 360s 超时守卫 |
  | **openSUSE** | `zypper --non-interactive refresh && zypper --non-interactive update -y` | 附带 300s 超时守卫 |
- **执行方式**：若用户勾选，将更新指令封装为 `firstboot-update.sh` 脚本注入 Guest `/opt/orchestella/firstboot.sh`，在 Guest Agent 初次握手就绪后后台静默拉起，并在终端顶部输出非阻塞日志进度。

## 架构演进与深模块改造设计

1. **抽象纯 JVM 向导状态机 `InstanceCreationWizardModel.kt`**：
   - 彻底与 Android View 解耦，维护当前步骤状态机、各步骤数据暂存、边界值校验与报错信息；
   - 暴露 `validateStorage(availableBytes, requestedBytes)`、`resolveMirrorUrls(distroId, mirrorChoice)`、`resolveUpdateCommand(distroId)`；
2. **网络源配置深模块 `DistroMirrorProvisioner.java`**：
   - 负责解析与替换对应发行版的包管理器配置文件；
   - 编写独立的单测，验证各发行版在不同镜像源选择下的配置文件文本生成正确性；
3. **初次启动引导脚本注入 `FirstBootProvisionPipeline.java`**：
   - 扩展已有的 `EmbeddedProvisionInput.java`，将网络源预设与 `firstboot-update.sh` 打包入 initramfs 或嵌入输入段，安全传递给 Guest。

## 验收标准 (Acceptance Criteria)

- [ ] **向导流程完整性**：点击创建实例不再一键秒开，而是拉起全流程向导界面，按序展示「存储与挂载」、「网络与镜像源」、「硬件分配」、「启动任务」；
- [ ] **自定义虚拟磁盘与预检**：支持用户自定义选择 4G/8G/16G/32G 或手动输入数值，当宿主存储空间不足（可用空间小于请求大小 + 2GB）时，阻止进入下一步并提示红字告警；
- [ ] **镜像源下拉生效**：在向导中选择清华源或中科大源后，创建出的实例内包管理器配置（如 `/etc/apk/repositories` 或 `/etc/apt/sources.list`）已正确替换为对应镜像站地址，无需手动编辑；
- [ ] **智能软件更新闭环**：当勾选“自动更新系统软件”时，新实例在初次启动后能正确触发对应的包管理器更新命令（Debian 执行 `apt-get update`，Alpine 执行 `apk update`），且不阻塞前台终端会话使用；
- [ ] **纯 JVM 单元测试覆盖**：新增 `InstanceCreationWizardModelTest.kt` 与 `DistroMirrorProvisionerTest.java`，覆盖所有镜像源生成格式、存储空间边界计算及各发行版更新命令映射，测试 100% 绿灯。
