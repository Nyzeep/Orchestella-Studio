日期：2026-10-21 ｜ 分支：`device/dv01-protected-payload` ｜ 基线：`35eec6e`

## 1. 结论

**Phase 0A/0B/0C 全部通过；DV-01 未执行，状态为 `BLOCKED_EXTERNAL`。**

本轮完成了此前缺失的四件事：

1. 用 NDK 27.0.12077973 构建出 Android arm64 `libfastlane_payload.so`，导出 `T AVmPayload_main`，三个 `PT_LOAD` 均为 `p_align=0x4000`；
2. 给 App 增加 payload `jniLibs` 打包属性和 `zipalign`/`symbol`/`zipinfo` 级别的 APK 校验；
3. 在现有 `AvfQaProbeInstrumentation` 中增加 `fastlane-dv01` 模式，并加了可 JVM 测试的参数/报告契约；
4. 通过零设备门禁：**313 tests / 8 skipped / 0 failures**，以及 payload APK、toolbox APK 两个门。

真机门没有通过，也没有被“绕过”：

- 当前连接的设备**不是**文档指定的 HONOR MEY-AN00；
- 两个 APK 在该设备上均被 OEM 安装限制拒绝：`INSTALL_FAILED_USER_RESTRICTED`；
- 包未安装，权限未授予，未创建 VM，未执行 instrumentation，因此没有 DV-01 真机 JSON、没有 20 次启停表，也没有任何 DV-01 通过声明。

需要设备操作者完成 USB 安装授权、连接指定 HONOR 设备后重跑。**未执行 root、解锁、SELinux/pvmfw 修改或安装限制绕过。**

### 2.2 三个真实构建缺陷（已修，仅构建/移植层）

零设备 CI 从未真正跑过 Android payload 目标，本轮首次构建暴露出：

1. `fastlane-payload/CMakeLists.txt` 的 `vm_payload_stub` 目标没有 include 目录，找不到 `fastlane/vm_payload_api.h`；
2. `transport.cpp` 在 `<linux/vm_sockets.h>` 之后才包含 `<sys/socket.h>`，bionic 下 `struct sockaddr` 不完整；
3. 两个 Android `.so` 没有 16 KB 链接对齐，`check-elf-16kb.sh` 报 `FAIL load_align`。

修复分别是：给 stub 目标加 `target_include_directories`；调整 include 顺序；给两个 Android 共享库加 `-Wl,-z,max-page-size=16384`。没有修改 FLN1 wire，也没有修改 payload 协议行为。

## 3. Phase 0B — APK 打包与校验

### 3.1 Gradle 变化

- 新属性 `orchestella.fastlane.payloadLibDir`，目录必须是 `arm64-v8a/libfastlane_payload.so` 的直接父目录；
- 配置期校验：目录/文件存在且不是 symlink；禁止目录中出现 `libvm_payload.so`；
- `sourceSets.main.jniLibs.srcDir(payloadRoot)`，不影响 `orchestella.qemu.nativeLibDir` 的路径；
- payload 构建使用 `useLegacyPackaging = false`，并通过 manifest placeholder `orcExtractNativeLibs` 把 `android:extractNativeLibs` 设为 `false`；普通构建仍为 `true`。这是让 `libfastlane_payload.so` 以 **stored + 16 KB 对齐** 进入 APK 的必要条件；
- 新增 `verifyFastlanePayloadApk`（依赖 `assembleDebug`），调用 `tools/fastlane-build/verify_payload_apk.py`：
  - entry 必须存在且 `compress_type == ZIP_STORED`；
  - local-header data offset 必须 16 KB 对齐；
  - `zipalign -c -P 16` 必须成功；
  - 解出 `.so` 后 `llvm-nm` 必须含 `T AVmPayload_main`；
  - APK 中不得有 `libvm_payload.so`；
  - `bin/sh` 必须存在（mode 0 按 P03/zipfuse 默认执行位记录）；
  - 失败非零退出。
- 新 task 已接入 `fastlaneZeroDeviceCheck`（有 payload 属性时）。

未修改版本号、签名、release channel。

### 3.3 一个需要后续注意的耦合

payload 构建把全局 `extractNativeLibs` 设为 `false`。这满足 AVF 从 APK 加载 payload 的 stored/对齐要求，但**尚未验证**同一构建若同时打包 QEMU `nativeLibDir` 的行为。DV-01 QA APK 没有带 QEMU 属性，因此本轮不受影响；后续若需要 payload + QEMU 同包，应单独做一次 QEMU 启停回归。

## 4. Phase 0C — DV-01 QA harness

### 4.1 入口与约束

`AvfQaProbeInstrumentation` 新增 `qaMode=fastlane-dv01`：

- 包名必须含 `.qa.dv01`，否则 `QA_DV01_PACKAGE_REQUIRED`；
- `qaRunToken` 必须为 16–64 位小写 hex；
- `qaPayload` 必须精确等于 `libfastlane_payload.so`；
- `qaToolboxSha` 必须为 64 位小写 SHA-256，并与 APK 内 `bin/manifest.json` 实际 SHA 比较；
- 输出：`files/avf-qa/fastlane-dv01-<token>.json`；
- schema：`orchestella.fastlane.dv01.v1`。

### 4.2 执行矩阵

- `AvfHiddenApiExemption.installOnce()`；
- `ReflectiveAvfPlatformAccess` 读取 access/exemption/permission/protected facts；反射读取 `getCapabilities` protected bit；builder probe `setProtectedVm(true)` / `setProtectedVm(false)`；
- `FastLaneLaunchSpec`：唯一 `instanceId`、`libfastlane_payload.so`、1 vCPU、1024 MB、256 MB encrypted storage、`DEBUG_NONE`、control/terminal/proxy/distcc 默认 9100–9103 且必须互异；
- `ReflectiveFastLaneApi` + `FastLaneSession`：start → 有界 `payloadReady()` → `openChannel(controlPort)` → FLN1 HELLO（空 token，报告记录 `auth_token=empty`）→ HELLO_OK → terminal PTY；
- terminal 命令：
  ```text
  /mnt/apk/bin/sh -c 'printf DV01_TERMINAL_OK; echo dv01 > /mnt/encryptedstore/dv01-marker; cat /mnt/encryptedstore/dv01-marker'
  ```
  断言 `DV01_TERMINAL_OK` 与 `dv01`，退出码 0；
- stop → 同 `instanceId` 再 start → 只读 `/mnt/encryptedstore/dv01-marker`，断言 `DV01_PERSIST_OK`/`dv01`；
- 20 次 create/run/stop，每次 stop 后 delete，并用 manager `get(name)` 做同名残留检查；`stop != CONFIRMED` 时中止并记录；
- 负例：`setProtectedVm(false)`、custom image config、错误 payload 名称、错误 vsock 端口；记录最早拒绝层/异常类型；
- 失败分类预置 `HIDDEN_API_BLOCKED`、`PERMISSION_DENIED`、`PROTECTED_UNAVAILABLE`、`PAYLOAD_VERIFY_FAILED`、`VSOCK_FAILED`、`STOP_UNCONFIRMED`；
- 报告不写 serial/IMEI/Android ID/真实 IP/MAC/账号/token/按键正文/截图/完整 logcat；终端输出只记录 byte 数与 contains 布尔值。

### 4.3 可 JVM 测试的契约

新增 `FastLaneDv01Contract`（`runtime/engine-fastlane`）和 11 个 JVM 测试，覆盖：

- token/SHA/payload 名称/port/cycle/alias/instanceId 校验；
- 报告必需 key 集合；
- 六类失败码映射。

这样参数与 schema 不依赖真机即可回归。

