# Fast Lane DV-01：protected payload 构建门与真机结果

日期：2026-10-21 ｜ 分支：`device/dv01-protected-payload` ｜ 基线：`35eec6e`（Phase 0）/ `6f369b2`（DV-01A 起点）

## 1. 结论

**Phase 0A/0B/0C 通过；DV-01 真机结果为 `DV01_CORE_PASS_TERMINAL_BLOCKED`。**

在操作者指定的替代 QA 设备（别名 `qa-alt-01`，API 36；不是文档中的 HONOR MEY-AN00）上：

- protected bit 可用，`setProtectedVm(true)` 接受，`setProtectedVm(false)` 抛 `UnsupportedOperationException`；
- create/run/payloadReady 成功（payloadReady 约 0.8–1.4 s）；
- control vsock HELLO/HELLO_OK 成功（caps=45，3–6 ms；最终运行使用默认 5100）；
- stop 为 `CONFIRMED`；第二次 start/stop 也为 `CONFIRMED`；
- **20/20 次 create/run/stop/delete 全部 pass**，最终 stop 264–391 ms，每轮 `residual=false`；
- **terminal PTY 失败已定位**：payload 返回 FLN1 7（`EXEC_FAILED`）；stage/errno 诊断显示 `realpath`、`stat`、`access(X_OK)` 都成功，但 `execve` 返回 **EACCES(13)**。guest audit 为 `avc: denied { execute_no_trans }`（`scontext=u:r:microdroid_app:s0`、`tcontext=u:object_r:system_file:s0`、`dev="fuse"`、`permissive=0`）。因此不是文件不存在、不是 ZIP mode 0、也不是 noexec 挂载，而是 Android 16 `microdroid_app` SELinux 策略缺少 `execute_no_trans` 的**外部平台阻塞**（DV-01A）；
- host 默认 vsock 端口已收敛为 payload 的 5100–5103，最终 20 轮使用默认值（未传 `qa*Port`）；
- encrypted storage marker 与跨 stop/start 持久化因此 `not-tested`；
- 负例：错误端口在 `FastLaneLaunchSpec` 层被拒绝；custom image 在 config builder 层被接受（未尝试 create）；错误 payload 未获得 typed rejection，标记 `unconfirmed`。

因此**没有** `DV01_CORE_PASS_TERMINAL_BLOCKED` 以外的通过声明，**不进入 DV-02**。DV-01A 的 terminal 结论是 `blocked_external`：需要平台侧 SELinux 策略授予 `execute_no_trans`（或提供平台支持的可执行挂载）才能继续；本轮没有修改 root/SELinux/pvmfw，也没有用 `/system/bin/sh`、encrypted storage 执行或 memfd 等方式绕过。

本结果不是在原 HONOR 设备上取得的；操作者已明确指定这台 API 36 替代设备执行本轮测试。报告只使用别名，不记录型号/序列号。

## 4. Phase 0C — DV-01 harness

`AvfQaProbeInstrumentation` 新增 `qaMode=fastlane-dv01`，要求包名含 `.qa.dv01`、token 16–64 hex、payload 精确为 `libfastlane_payload.so`、toolbox SHA 与 APK 内 `bin/manifest.json` 一致。

Harness 行为：

- `AvfHiddenApiExemption.installOnce()`；`ReflectiveAvfPlatformAccess` 读取 facts；反射读 protected bit；builder probe `setProtectedVm(true/false)`；
- `FastLaneLaunchSpec`：1 vCPU、1024 MB、256 MB encrypted storage、`DEBUG_NONE`、四个互异端口；
- `ReflectiveFastLaneApi` + `FastLaneSession`：start、有界 payloadReady、control FLN1 HELLO（空 token，报告记录 `auth_token=empty`）、terminal PTY、stop、同 instance 再 start 验证 storage、20 次 create/run/stop/delete、残留检查、负例；
- 报告：`files/avf-qa/fastlane-dv01-<token>.json`，schema `orchestella.fastlane.dv01.v1`；
- 安全：不写 serial/IMEI/Android ID/账号/token/按键正文/截图/完整 logcat；终端只记录 byte 数和固定错误码；
- 连接/关闭有界：`openChannelBounded` 防止 binder `connectVsock` 无限阻塞；terminal close 有 2 s 看护线程；
- 11 个 JVM `FastLaneDv01Contract` 测试覆盖参数、schema key 和失败码映射。

### 4.1 端口契约（已修复）

payload 的默认 vsock 端口是 **5100/5101/5102/5103**（`runtime.h`），而 harness 原默认是 **9100–9103**。使用 9100 时 control/terminal connect 被对端 reset（`Connection reset by peer`），payloadReady 仍然成功，因此这是一个容易误判的集成缺口。

DV-01A 已把 `FastLaneDv01Contract` 的默认值改为 **5100–5103**，并新增 JVM parity 测试：直接读取 `fastlane-payload/include/fastlane/runtime.h`，断言 host 默认值与 payload 一致。最终 20 轮运行**没有传** `qaControlPort/qaTerminalPort/qaProxyPort/qaDistccPort`，control HELLO/HELLO_OK 成功（6 ms），证明默认命令可用。未改 payload 字节，也未改 FLN1 wire。

## 7. 终端失败分析（DV-01A 已定位为外部 SELinux 阻塞）

1. **vsock 正常**：control/terminal 的 connect 都成功；默认 5100/5101 下 control HELLO/HELLO_OK 为 6 ms。不是端口或 vsock 连接问题。
2. **分层诊断**：payload 的 OPEN_PTY 错误消息现在携带 stage/errno（只改 ERROR message 文本，不改 FLN1 格式或字节）。设备返回 `fln1=7 execve_errno_13`：`realpath`、`stat`、`access(X_OK)` 全部成功，失败发生在 `execve`。
3. **排除 ENOENT/ZIP mode**：APK 中 `bin/sh` 存在（1,115,944 bytes），`external_attr` mode 0；zipfuse 对 `bin/` 的默认执行位应生效，且 `access(X_OK)` 成功证明实际 mode 可执行；`/mnt/apk/bin/sh` 的 realpath/stat 也成功。因此不是路径不存在，也不是缺少执行位。
4. **排除 noexec**：把同一 payload 的 OPEN_PTY 指向 `/mnt/apk/bin/manifest.json`（`bin/` 下的普通非 ELF 文件）。若挂载允许执行，应返回 ENOEXEC(8)；实际仍返回 EACCES(13)。另外，Linux `access()` 自 2.6.20 起也遵守 `MS_NOEXEC`，`access(X_OK)` 成功本身就不支持 noexec 挂载。
5. **直接证据**：DEBUG_FULL 诊断运行的 guest audit：

```text
avc: denied { execute_no_trans } for path="/mnt/apk/bin/sh" dev="fuse"
scontext=u:r:microdroid_app:s0 tcontext=u:object_r:system_file:s0 tclass=file permissive=0
```

6. **策略解释**：`/mnt/apk` 由 zipfuse 以 `context=u:object_r:system_file:s0` 挂载；payload 进程域是 `microdroid_app`。A16 policy 有 `allow coredomain system_file:file execute`（因此 `access(X_OK)` 成功），但没有给 `microdroid_app` 对 `system_file` 的 `execute_no_trans`；execve 无 domain transition 时必须检查 `execute_no_trans`，于是返回 EACCES。`bin/` 的 zipfuse 执行位本身没有问题。
7. **结论**：这不是 APK 打包或 toolbox 文件可直接修复的问题；需要平台侧策略变更（或平台支持的可执行挂载）。按停止条件记为 `blocked_external`；没有修改 root/SELinux/pvmfw，也没有用 `/system/bin/sh`、encrypted storage 执行、memfd、chmod 等方式绕过。
8. **影响**：storage marker/持久化、terminal 输出断言仍为 `not-tested`；本轮不能宣称 DV-01 全通过，不能进入 DV-02。

## 10. 结论与后续

- DV-01：**`DV01_CORE_PASS_TERMINAL_BLOCKED`**。核心生命周期、control 与 20 次启停通过；terminal/storage 未通过。
- DV-01A 已完成定位：terminal 的 `execve EACCES` 是 Android 16 `microdroid_app` 对 `system_file` 缺少 `execute_no_trans` 的 **SELinux 平台策略阻塞**，不是 toolbox 文件、ZIP mode、ENOENT 或 noexec 挂载。该结论有 stage/errno 诊断、manifest 非 ELF 差分和 guest AVC 直接证据。
- 本轮已交付：host 默认端口收敛为 5100–5103（含读取 `runtime.h` 的 parity 测试）、`verify_payload_apk.py` 的 v2+v3 签名门、payload OPEN_PTY 的 stage/errno 诊断（仅 ERROR message 文本，无 wire 变更）、315 tests / 8 skipped 的零设备门禁。
- **不进入 DV-02**，不宣称完整 DV-01。必须先由平台侧授予 `execute_no_trans`（或提供平台支持的可执行挂载），再重跑 terminal + storage + 负例 + 20 轮；在此之前 terminal/storage 保持 `not-tested`。
- 本轮未修改 accepted ADR、版本号、release channel 或签名身份；未 root/unlock、未改 SELinux/pvmfw、未绕过安装限制。
- v2→v3 签名是现有 debug 证书上的兼容性修复；签名配置未换 key、未改 QA channel。
