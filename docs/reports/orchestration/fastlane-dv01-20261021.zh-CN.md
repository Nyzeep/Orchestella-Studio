# Fast Lane DV-01：protected payload 构建门与真机结果

日期：2026-10-21 ｜ 分支：`device/dv01-protected-payload` ｜ 基线：`35eec6e`

## 1. 结论

**Phase 0A/0B/0C 通过；DV-01 真机结果为 `DV01_CORE_PASS_TERMINAL_BLOCKED`。**

在操作者指定的替代 QA 设备（别名 `qa-alt-01`，API 36；不是文档中的 HONOR MEY-AN00）上：

- protected bit 可用，`setProtectedVm(true)` 接受，`setProtectedVm(false)` 抛 `UnsupportedOperationException`；
- create/run/payloadReady 成功（payloadReady 约 0.8–1.2 s）；
- control vsock HELLO/HELLO_OK 成功（caps=45，约 3 ms）；
- stop 为 `CONFIRMED`；第二次 start/stop 也为 `CONFIRMED`；
- **20/20 次 create/run/stop/delete 全部 pass**，stop 382–527 ms，每轮 `residual=false`；
- **terminal PTY 失败**：payload 返回 FLN1 错误 7（`EXEC_FAILED`），映射为 `TOOLBOX_EXEC_FAILED`；`/mnt/apk/bin/sh -c ...` 没有产生 `DV01_TERMINAL_OK`；
- encrypted storage marker 与跨 stop/start 持久化因此 `not-tested`；
- 负例：错误端口在 `FastLaneLaunchSpec` 层被拒绝；custom image 在 config builder 层被接受（未尝试 create）；错误 payload 未获得 typed rejection，标记 `unconfirmed`。

因此**没有** `DV01_CORE_PASS_TERMINAL_BLOCKED` 以外的通过声明，**不进入 DV-02**。

本结果不是在原 HONOR 设备上取得的；操作者已明确指定这台 API 36 替代设备执行本轮测试。报告只使用别名，不记录型号/序列号。

## 3. Phase 0B — APK 打包与签名

### 3.1 打包

- 新属性 `orchestella.fastlane.payloadLibDir`，校验目录/`.so` 存在且不是 symlink，禁止 `libvm_payload.so`；
- payload builds 使用 `useLegacyPackaging=false`，并通过 `orcExtractNativeLibs` placeholder 设置 `android:extractNativeLibs=false`；普通构建保持 `true`；
- 新增 `verifyFastlanePayloadApk`：stored、16 KB data offset、`zipalign -c -P 16`、`llvm-nm` 符号、无 `libvm_payload.so`、`bin/sh` 存在；
- task 接入 `fastlaneZeroDeviceCheck`；未改版本号、release channel。

### 3.2 v2-only 签名是第一个真机阻塞（已修复）

首次真机 create 返回 `VM_CREATE_FAILED`，平台消息分类为 `signature`；安全诊断显示：

```text
Failed to create idsig
Fallback to v2 when v3 block not found is not yet implemented
No APK Signature Scheme block ... ID: 4031998144
```

QA APK 原本只有 v2 签名（debug key）。在**现有 debug signing config** 上启用 `enableV3Signing`/`enableV4Signing` 后，证书、applicationId、QA channel 均不变，APK 变为 v2+v3（v4 仍为 false），create 随即通过。

这是设备 AVF `idsig` 路径对 v3 的最低要求，不是密钥/渠道变更；若项目规则要求“签名配置完全不动”，这一处需要主协调复核。

## 4. Phase 0C — DV-01 harness

`AvfQaProbeInstrumentation` 新增 `qaMode=fastlane-dv01`，要求包名含 `.qa.dv01`、token 16–64 hex、payload 精确为 `libfastlane_payload.so`、toolbox SHA 与 APK 内 `bin/manifest.json` 一致。

Harness 行为：

- `AvfHiddenApiExemption.installOnce()`；`ReflectiveAvfPlatformAccess` 读取 facts；反射读 protected bit；builder probe `setProtectedVm(true/false)`；
- `FastLaneLaunchSpec`：1 vCPU、1024 MB、256 MB encrypted storage、`DEBUG_NONE`、四个互异端口；
- `ReflectiveFastLaneApi` + `FastLaneSession`：start、有界 payloadReady、control FLN1 HELLO（空 token，报告记录 `auth_token=empty`）、terminal PTY、stop、同 instance 再 start 验证 storage、20 次 create/run/stop/delete、残留检查、负例；
- 报告：`files/avf-qa/fastlane-dv01-<token>.json`，schema `orchestella.fastlane.dv01.v1`；
- 安全：不写 serial/IMEI/Android ID/账号/token/按键正文/截图/完整 logcat；终端只记录 byte 数和固定错误码；
- 连接/关闭有界：`openChannelBounded` 防止 binder `connectVsock` 无限阻塞；terminal close 有 2 s 看护线程；
- 11 个 JVM `FastLaneDv01Contract` 测试覆盖参数、schema key 和失败码映射。

### 4.1 端口契约不一致（重要）

payload 的默认 vsock 端口是 **5100/5101/5102/5103**（`runtime.h`），而 harness/简报默认是 **9100–9103**。使用 9100 时 control/terminal connect 被对端 reset（`Connection reset by peer`），payloadReady 仍然成功，因此这是一个容易误判的集成缺口。

本轮最终执行使用显式覆盖：

```text
qaControlPort=5100 qaTerminalPort=5101 qaProxyPort=5102 qaDistccPort=5103
```

control 随即成功。后续应把 payload 默认值与 harness 默认值收敛为单一事实来源；本轮未改 payload 字节，也未改 FLN1 wire。

## 7. 终端失败分析

- control 和 terminal 的 vsock **连接**都成功；不是 vsock/端口问题。
- payload 对 terminal `OPEN_PTY` 返回 FLN1 7（`EXEC_FAILED`），即执行 `/mnt/apk/bin/sh` 失败；没有 PTY 输出。
- 最可能的层：APK 内 `bin/sh` 在 guest 的 `/mnt/apk` 挂载中不可执行，或该条目没有显式 exec mode。P03 依赖 zipfuse 默认执行位；这台设备的 Microdroid APK 挂载路径没有满足该假设。
- 因此 storage marker 写入/读取、stop-start 持久化、terminal 输出断言均未测试；不能宣称 DV-01 全通过。
- 下一步应修 toolbox 打包（显式 0755 的 `bin/sh` / 验证 `/mnt/apk/bin` 挂载），然后重跑 terminal 部分；不改 FLN1 wire、不改 pvmfw/SELinux。

## 8. 失败分类与负例

| 类别 | 状态 |
| --- | --- |
| `HIDDEN_API_BLOCKED` | not-tested（exemption installed） |
| `PERMISSION_DENIED` | not-tested（MANAGE granted） |
| `PROTECTED_UNAVAILABLE` | not-tested（protected bit + setProtectedVm true accepted） |
| `PAYLOAD_VERIFY_FAILED` | not-tested（v3 create/run 成功；wrong payload 未产生 typed rejection） |
| `VSOCK_FAILED` | not-tested（control/terminal connect 均成功） |
| `STOP_UNCONFIRMED` | not-tested（first/second 均 CONFIRMED；20 轮均 CONFIRMED） |
| `TOOLBOX_EXEC_FAILED` | **observed**（FLN1 7） |
| `NEGATIVE_CASE_UNCONFIRMED` | observed（wrong payload 未在 10 s 内给出 typed rejection） |

负例明细：

- `wrong_vsock_port`：`FastLaneLaunchSpec` 拒绝重复端口（`CONFIG_INVALID`）；
- `custom_image_config`：config builder 接受（未创建 VM）；create 层 `not-tested`；
- `wrong_payload_name`：VM 未 ready，但 `waitForExit` 未给出 typed rejection，标记 `unconfirmed`，未计为通过。

## 10. 结论与后续

- DV-01：**`DV01_CORE_PASS_TERMINAL_BLOCKED`**。核心生命周期、control 与 20 次启停通过；terminal/storage 未通过。
- **不进入 DV-02**，不宣称完整 DV-01。
- 必须修 toolbox `bin/sh` 的 guest 可执行性，并重跑 terminal + storage + 负例；同时把 payload/harness 默认端口收敛为单一事实来源。
- 本轮未修改 accepted ADR、版本号、release channel；未 root/unlock、未改 SELinux/pvmfw、未绕过安装限制。
- v2→v3 签名是现有 debug 证书上的兼容性修复；如果项目要求签名配置绝对不变，请主协调在合并前复核。
