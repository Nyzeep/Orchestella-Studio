## 安装

### 你需要哪几个包

| 包 | 文件名 | 说明 |
| :--- | :--- | :--- |
| 主包（必需） | `Orchestella-Studio-v0.6.0-release.apk` | 应用本体 + QEMU 完整内核路径（完整 Linux、systemd、SSH、七种发行版） |
| pVM 加速扩展包（可选） | `Orchestella-Accelerator-v0.6.0-release.apk` | pVM payload、编译器引擎与 `PVM-COMPILER-MANIFEST`；只有需要在 pVM 车道跑编译时才装 |

两条硬规则：

1. **两个包的 `versionCode` 必须一致**（0.6.0 均为 600）。不一致时应用会明确拒绝启用扩展包，
   不做尽力加载。
2. **只装主包 = 只有 QEMU 车道。** 完整内核、systemd、SSH 与发行版目录都可用；
   pVM 相关入口会显示"未安装 pVM 加速扩展包"。

### 小米 / HyperOS 用户注意（踩过的坑）

- **新装应用需要屏幕上的确认**；锁屏状态下 ADB 安装必然失败（`INSTALL_FAILED_USER_RESTRICTED`）。
  装包前请解锁并保持亮屏，等系统弹窗确认。
- **已存在包的更新不受这条限制**，所以不要为了"干净安装"先卸载 —— 卸载会带走应用私有目录
  里的实例数据。
- `settings put global adb_install_need_confirm 0` 对 HyperOS 无效，仍会被拦。

### 授予 pVM 权限

```bash
adb shell pm grant io.github.nyzeep.orchestella android.permission.MANAGE_VIRTUAL_MACHINE
```

返回 `granted=true` **不等于** pVM 车道可用：设备还必须注册 `virtualizationservice`。
当前测试机没有注册该服务，授权后仍然回落 QEMU —— 缺的是服务，不是权限。

## 校验

每个 Release 附件都提供 `SHA256SUMS`；下载后可核对：

```bash
sha256sum -c SHA256SUMS
```

APK 身份（可选，需要 `aapt2`）：

```bash
aapt2 dump badging Orchestella-Studio-v0.6.0-release.apk | head -1
```

签名证书 SHA-256 会在本页 §6 记录（打 tag 时由维护者填入）。

## 已知限制

- **proot 车道需要 28 域包**：该车道只存在于 `-Porchestella.qaTargetSdk=28` 的隔离通道。
- **真实 AVF Guest 成功样本仍为 0**：当前测试设备声明了 AVF 能力但未注册
  `virtualizationservice`，pVM 车道在决策层被拒后回落 QEMU。
- **扩展包的包可见性修复尚未真机复测**：源码已修（`<queries>` 按通道注入），
  装包后的实际判定待下一设备轮验证。
- **UML 仅为研究线**：编译角色已被实测否定（2,000 函数夹具中位 940 ms，
  同轮 native 460 ms，即 2.04×，劣于 `≤1.5×` 判据），仅保留长驻 / 容器方向。
- **16 KB 页**：ELF / APK 对齐已过校验，真机运行未测。

### 2026-10-30 第三次打包（v3，修「实例不可用」）

用户报障：下载 0.6.0 安装后创建 Linux 实例直接不可用。根因不在运行逻辑，而在**包内容**：

- `app/src/main/jniLibs/arm64-v8a/libdroidlayer_qemu.so`（132 MB）与 `libgvproxy.so`（12 MB）
  按许可证要求不入库；会话 25 为让本地 16 KB 门通过，把工作树里的副本移进了
  `artifacts/qa-jniLibs-4k-arm64/`。此后 `assembleRelease` 仍「构建成功」，打出的 APK 只剩
  `assets/Image`（52 MB 内核）与 initramfs，`lib/arm64-v8a/` 里只有 gles/virgl 两个库。
- 运行期 `NativeExecutableStore.ensure()` 先找 `nativeLibraryDir/libdroidlayer_qemu.so`
  （不存在），再找 APK 内 `lib/arm64-v8a/libdroidlayer_qemu.so`（不存在），抛
  `missing from both nativeLibraryDir and the APK` —— 这就是用户看到的「实例不可用」。
- **修复**：把两个 `.so` 拷回 `app/src/main/jniLibs/arm64-v8a/` 重打（APK 59.9 MB → 102.4 MB）。
- **新增门禁** `tools/release/check_runtime_payload.py`：按 `runtime-artifacts-v1.sha256`
  逐字节校验收件（`assets/Image`、`initramfs.cpio.gz`、`lib/arm64-v8a/libdroidlayer_qemu.so`），
  `libgvproxy.so` 缺失只告警；已接进 `release.yml` 的 `publish-draft`，缺载荷直接拒绝建 Release。
  对旧包复现 FAIL、对新包 OK（7 例单测）。

**真机复验（2026-10-30，Xiaomi 25102RKBEC / Android 17 / SDK 37 / 4 KB 页）**

  而 protected VM 只收 Google/OEM 签名镜像。故本轮不发布 pVM 加速扩展包。

### 2026-10-30 第四次打包（v4，加 pVM 扩展包 + 开发者工具链）

用户在同一台真机上体验后反馈两件事：`apt` 与常用开发命令"用不了"；以及希望开发者版本直接带上
pVM 加速包。

- **"开发命令用不了"的真因不是 apt**：实测 `apt update` / `apt install make` 全部正常，
  `which` 显示 `git/sudo/systemctl/ssh/curl/wget` 都在，缺的是 `gcc`、`make`、`python3`、`vim`
  ——基础包清单（`guest-assets/scripts/orchestella-guest-provision.sh`）本来就只有终端与网络工具。
  另外每一条 apt 命令都会打印
  `N: Ignoring file 'ubuntu.sources.orchestella-original' ... invalid filename extension`，
  因为 `runtime-entry.sh` 把云镜像的 deb822 源**备份在 sources.list.d 里**，apt 会去读这个目录。
  这条噪声让人以为包管理器坏了。
- **已修（源码）**：备份改到 `/var/lib/orchestella/apt-backup/`；`apt install vim` 还会卡在
  tzdata 的交互选择上（70% 停住），需要在 provisioning 阶段预置 timezone/debconf
  ——下次 guest 产物重建一并处理（本机没有 aarch64 交叉工具链，initramfs 无法本地重打）。
- **已修（应用侧，本版可装）**：`实例 → 桌面与开发工具` 顶部新增"开发者工具链（基础镜像未预装）"
  卡片，给出当前发行版的安装命令，支持「在终端填入命令」（打开终端 + 预填 `发送命令` 对话框，
  用户确认才执行）与「复制命令」。**实测** Ubuntu 24.04 内装 `build-essential python3 vim`
  共 80 MB / 约 8 分钟，装完 `gcc`、`make`、`python3` 均在 `/usr/bin` 可用。
- **pVM 扩展包（本版新增附件）**：`Orchestella-Accelerator-v0.6.0-release.apk`，127 MB，
  applicationId `io.github.nyzeep.orchestella.accel`，versionCode 600，与主包同一张证书。
  **修掉一个会毁掉主包的缺陷**：`.accel` 后缀过去只加在 debug 构建类型里，release 出来的扩展包
  包名与主包**完全相同**（同 versionCode、同签名）——装上去会把主包覆盖成一个没有启动入口的包。
  现在两种构建类型都带后缀，`verify_apk.py --expected-application-id ...accel` 通过。
  另：`targetSdk 28` 触发的 lint `ExpiredTargetSdkVersion` 在扩展模块内显式关闭并写明理由
  （自分发、不含代码、与加速车道基线一致）。
- **本机装不上扩展包**：`adb install` / `pm install` / 会话式安装一律
  `INSTALL_FAILED_USER_RESTRICTED`（HyperOS 对新应用安装的门），与主包更新无关。
  发布说明已写明"请用手机点安装"。
- 主包 SHA-256 `16be112c…2ed8`（102,385,582 B），扩展包 `89f10c13…95a5`（132,902,519 B）。
