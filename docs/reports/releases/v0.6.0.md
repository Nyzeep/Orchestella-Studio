## 安装

### 你需要哪几个包

| 包 | 文件名 | 说明 |
| :--- | :--- | :--- |
| 主包（必需） | `Orchestella-Studio-v0.6.0-release.apk` | 应用本体 + QEMU 完整内核路径（完整 Linux、systemd、SSH、七种发行版） |
| pVM 加速扩展包（可选） | `Orchestella-Accelerator-v0.6.0-release.apk` | pVM payload、编译器引擎与 `PVM-COMPILER-MANIFEST`；只有需要在 pVM 车道跑编译时才装 |

两条硬规则：

1. **两个包的 `versionCode` 必须一致**（0.6.0 均为 600）。不一致时应用会明确拒绝启用扩展包，
   不做尽力加载。
2. **只装主包 = 只有 QEMU 车道。** 完整内核、systemd、SSH 与发行版目录都可用；
   pVM 相关入口会显示"未安装 pVM 加速扩展包"。

### 小米 / HyperOS 用户注意（踩过的坑）

- **新装应用需要屏幕上的确认**；锁屏状态下 ADB 安装必然失败（`INSTALL_FAILED_USER_RESTRICTED`）。
  装包前请解锁并保持亮屏，等系统弹窗确认。
- **已存在包的更新不受这条限制**，所以不要为了"干净安装"先卸载 —— 卸载会带走应用私有目录
  里的实例数据。
- `settings put global adb_install_need_confirm 0` 对 HyperOS 无效，仍会被拦。

### 授予 pVM 权限

```bash
adb shell pm grant io.github.nyzeep.orchestella android.permission.MANAGE_VIRTUAL_MACHINE
```

返回 `granted=true` **不等于** pVM 车道可用：设备还必须注册 `virtualizationservice`。
当前测试机没有注册该服务，授权后仍然回落 QEMU —— 缺的是服务，不是权限。

## 变更摘要

### 新增

- **双包发布形态**：主包不再携带 pVM payload 与编译器引擎，改由 `…accel` 扩展包承载。
- **应用图标**：自适应图标（前景 / 背景 / monochrome 主题图标）+ 五档密度 + 传统方形与圆形。
- **36 域 QEMU 车道**：`targetSdk 36` 下 QEMU/gvproxy 以 `nativeLibraryDir` 绝对路径 exec 成功
  （执行类 AVC = 0），guest 完成 systemd 启动并给出 root shell。
- `CHANGELOG.md` 与发布签名向导（`docs/standards/RELEASE-SIGNING.md`）。

### 修复

- 扩展包在本机被误判"未安装"（`<queries>` 未声明扩展包 → 包可见性过滤）。
- 主界面七张发行版卡片的标签前景色与底色相同导致文字不可见（最低 1.00:1 → 5.01:1 以上）。
- 墙纸被 `Gravity.FILL` 双向拉伸变形。
- 终端背景、墙纸等位图背景统一为 cover 裁切语义（等比铺满 + 居中裁切，绝不非等比拉伸）。
- 图标按钮被 TalkBack 念出无意义英文；实例列表读取失败复用了"创建失败"文案。

### 改进

- 桌面虚拟键条触控高度 44dp → 48dp。
- 通知渠道名称与描述中文化（每次启动刷新，保留用户自定义的重要性等级）。
- 端口转发表单标点统一全角。
- README 重写为中英双语，含四车道能力矩阵、安装指南、Roadmap 与许可证致谢。

## 校验

每个 Release 附件都提供 `SHA256SUMS`；下载后可核对：

```bash
sha256sum -c SHA256SUMS
```

APK 身份（可选，需要 `aapt2`）：

```bash
aapt2 dump badging Orchestella-Studio-v0.6.0-release.apk | head -1
```

签名证书 SHA-256 会在本页 §6 记录（打 tag 时由维护者填入）。

## 已知限制

- **proot 车道需要 28 域包**：该车道只存在于 `-Porchestella.qaTargetSdk=28` 的隔离通道。
- **真实 AVF Guest 成功样本仍为 0**：当前测试设备声明了 AVF 能力但未注册
  `virtualizationservice`，pVM 车道在决策层被拒后回落 QEMU。
- **扩展包的包可见性修复尚未真机复测**：源码已修（`<queries>` 按通道注入），
  装包后的实际判定待下一设备轮验证。
- **UML 仅为研究线**：编译角色已被实测否定（2,000 函数夹具中位 940 ms，
  同轮 native 460 ms，即 2.04×，劣于 `≤1.5×` 判据），仅保留长驻 / 容器方向。
- **16 KB 页**：ELF / APK 对齐已过校验，真机运行未测。
