# 国产 OEM 的 AVF 与 ADB 授权现状（研究票 R5 结论）

> 日期：2026-09-05。方法：主线程串行检索（IT之家/搜狐报道 + Google Play 设备目录数据 + 开发者社区实测帖）。
> 结论状态：覆盖面数据**有来源**；ADB 限制矩阵来自**社区实测**（非官方文档），标注为社区证据。

## 1. AVF 覆盖面（对 L2 目标人群最重要的数据）

- **Google Play Console 设备目录显示已有 361 款设备型号声明支持 AVF**——包括 Pixel 6 起全系、以及 **OnePlus、小米、摩托罗拉、vivo、Tecno、OPPO** 等厂商机型（IT之家转引 Play Console 数据，2025）。
- 驱动因素：Google 自 Android 15 起对**新发布芯片**强制 AVF 支持；AVF 仅 ARM64。
- **必须保留的三个折扣**（防止把"支持 flag"读成"能跑"）：
  1. 声明 feature flag ≠ Terminal 应用可用（三星曾禁用 Terminal 但部分机型仍报 flag）；
  2. 声明支持 ≠ 第三方 custom VM 可用（非保护 VM 支持因芯片而异——Snapdragon 8 Elite 系已知缺非保护 VM）；
  3. 声明支持 ≠ custom VM 网络可用（原型票 17 观察项）。
- **对 spec 的校准**：L2 目标人群显著大于"Pixel only"的旧估计；国产主流品牌 2024 年后的旗舰/中高端有实质覆盖，但**逐机型验证只能靠原型与用户反馈**，spec 中以能力检测为准、覆盖率数据为营销参考。

## 2. ADB 授权的 OEM 限制矩阵（社区实测证据）

| OEM/OS | 限制 | 对我们 L2 授权（adb pm grant / Shizuku）的影响 |
| --- | --- | --- |
| 小米 MIUI/HyperOS | "USB 安装"与"USB 调试（安全设置）"要求**插 SIM 卡 + 登录小米账号**；HyperOS（小米 15）默认禁用 USB APK 安装；部分 adb 命令被"安全设置"门控 | 普通 USB 调试仍可用（pm grant 理论可走普通调试通道）；"安全设置"门控是否波及 pm grant **未实测**（UNCERTAIN，待原型）；授权向导需 per-OEM 步骤页 |
| OPPO ColorOS | adb install 历史上要求**登录 OPPO 账号**；企业/自动化可申请免账号安装权限 | pm grant 同上待实测；向导需账号提示页 |
| vivo OriginOS | 安装与调试类操作有**账号验证 + 额外安全开关** | 同上 |
| 其他（一加/摩托/Tecno 等） | 社区未见系统性额外门控报告 | 按标准流程 |

- 共性风险：国产 OEM 的安全门控**目标是 adb install，不必然覆盖 pm grant**——但无一手证据，向导设计必须把"授予失败"作为一等场景处理（清晰报错 + 备选路径），不能假设一次成功。
- 无线调试（Shizuku 路径）：受各厂对无线调试的支持差异影响，向导中作为优先路径的同时必须保留 ADB 命令兜底（ADR-0003 已定）。

## 3. 对已关闭决策的影响检查

- ADR-0003（L1+L2 双级出厂）：**不受影响，反而被覆盖面数据加强**（L2 可达人群比旧估计大）。
- ADR-0004（兼容性地板）：不受影响。
- 授权向导（ADR-0003）：新增设计输入——per-OEM 步骤页 + 失败兜底为一等需求；这是 spec 的 UX 章节 内容，不需要重开决策。

## 4. 遗留不确定（进 spec 的"待实测"清单）

1. pm grant 在 MIUI"安全设置"门控下是否可用（待真机）。
2. 361 款机型中 custom VM（非保护 VM + 网络）的实际可用比例（待原型 + 众包反馈）。
3. Shizuku 在各厂无线调试实现下的成功率（待用户数据）。
