# Podroid 源码深度分析（研究票 R1 结论）

> 日期：2026-09-05。方法：浅克隆 main @ `bc7477fb`（2026-09-03）+ GitHub API。
> 结论状态：**已核实**（所有文件引用均来自实际源码；作者自述的 CLAUDE.md 已与源码交叉验证，属实）。
> 本文档是 wayfinder 决策票「Podroid 源码深度分析」的 Answer 存档。

## 1. 总体架构

干净的 `VmEngine` 抽象 + 双后端 + 运行时路由（`app/src/main/java/com/excp/podroid/engine/`）：

```kotlin
interface VmEngine {
    val state: StateFlow<VmState>; val bootStage: StateFlow<String>; val consoleText: StateFlow<String>
    val terminalSession: TerminalSession?; val backendId: String
    val qmpClient: QmpClient?                     // QEMU 专属；AVF 为 null
    fun openHostTransport(): HostTransport?       // guest→Android 桥
    suspend fun start(portForwards: List<PortForwardRule>, config: VmConfig)
    fun stop(); fun createTerminalSession(...): TerminalSession
    suspend fun addPortForward(rule); suspend fun removePortForward(rule)
}
```

- **QemuEngine**（~900 行）：QEMU 11.0.2 TCG（`-accel tcg,thread=multi`）、SLIRP、QMP、三个 virtio-console Unix socket + serial socket。
- **AvfEngine**（1,082 行）：因 AVF Java API（`android.system.virtualmachine.*`，含 `VirtualMachineCustomImageConfig`）是隐藏 @SystemApi，**全部走反射 + HiddenApiBypass**（`AvfReflect.kt`：`setKernelPath`/`setInitrdPath`/`addDisk(path,writable)`/`setNetworkSupported(true)`/`setGpuConfig`）。以**非保护 VM** 启动与 QEMU 相同的 custom kernel+initrd+squashfs。
- 无 proot/chroot——"not a chroot or proot trick" 属实。
- **路由是运行时能力检测**（`EngineHolder.kt` + `EngineSelection.kt`）：`AvfDiagnostics.probe()`（binder 探测：feature `android.software.virtualization_framework`、两个权限授予、服务可达、custom-VM 支持）→ `AvfCapabilities.choose()`：`CAPABILITY_NON_PROTECTED_VM=2` 才可行；仅保护 VM → Unsupported（"protected VM 需要 pvmfw 签名载荷"）。`decideBackend()` 是纯函数、有单测。强制 AVF 但设备不支持 → 透明回退 QEMU 并给出本地化原因。

## 2. Guest Kernel

- 上游源码 Docker 构建：**Linux 7.1.5**（2026 当前版），arm64 defconfig + merge_config；版本 pin 在 `gradle.properties`。无 CI——维护者本机 `build-all.sh` 构建。
- 以 APK asset（`vmlinuz-virt`）分发，首启解压到 filesDir（仅 size+stamp 校验，**无加密校验**）。
- Kernel config（`podroid_kernel.config`，Dockerfile 校验失败即中断）：virtio 全家内置（balloon/input 关）；9P + SQUASHFS(zstd) + OVERLAY_FS + EXT4(UNICODE) + FUSE；cgroup v2 全套 + 全部 namespace（含 USER_NS/NET_NS）+ SECCOMP + BPF——rootless Podman 套件；完整 netfilter/nftables + TUN/VETH/BRIDGE；ZRAM swap；`mitigations=off`（TCG 下认为安全）；无 DRM/FB（无头，`-display none`）；大片 USB 驱动内置；强制 BINDERFS。

## 3. Rootfs / Distro 模型

- **单发行版：Alpine 3.24 (aarch64)**。minirootfs tarball + podman/crun/docker/lxc/dropbear/nftables/fuse-overlayfs/shadow-uidmap 等，`mksquashfs -comp zstd`。
- 运行时布局（两后端一致）：只读 squashfs（/dev/vdb）= lower；持久 raw ext4 `storage.img`（/dev/vda）= overlay upper；initramfs `init-podroid` 叠加后 `switch_root`（非 chroot——保 podman exec 的 mount ns 正确性）。**App 升级换 squashfs 不丢数据**；版本化迁移脚本系统（`/etc/podroid/migrations/`）。
- 无密码学校验（kernel/Alpine/QEMU 均裸 wget）；全部存 app 私有 filesDir；唯一共享面是 Downloads（QEMU 走 9p + MANAGE_EXTERNAL_STORAGE）。

## 4. 宿主↔Guest 集成（按后端非对称——作者自称"第一大 bug 来源"）

- **vsock 仅 AVF**：控制通道 9100（RESIZE/ADD/REMOVE/PING/SYNC 行协议）、host bridge 9101、9p rendezvous 200000；guest 侧 `podroid-vsock-agent.c`。
- **QEMU 等价物**：三个 virtio-console + serial over Unix sockets（terminal/ctrl/host/serial/qmp）。
- **Guest agent**：`podroid-hostd.c` 多调用二进制（hostd/notify/forward/open/power/headless），base64 行协议：NOTIFY（Android 通知）、FORWARD ADD/REMOVE/LIST（DataStore 持久 + 实时对账）、OPEN url（ACTION_VIEW）、POWER、HEADLESS。
- **文件共享**：QEMU = virtio-9p（security_model=none）；AVF = **手写 Kotlin 9p2000.L server（~886 行）over vsock fd**。无 virtiofs。
- **无剪贴板同步**；有通知/URL/端口转发（两后端实时对账）；QMP 动态 hostfwd（避免坏 hostfwd 杀死 SLIRP 启动）。

## 5. GUI / 终端

- 终端：**vendored Termux fork**（`MatanZ/termux-app:sixel4`）两个 Gradle 模块 + NDK JNI；native relay `podroid-bridge.c` splice PTY↔hvc0；SIGWINCH 防抖写 RESIZE。AVF 侧 `ConsoleFanout` 把 console 桥到 Unix socket 使同一 bridge 复用。
- 图形：guest 内 **Xvnc（TigerVNC）** 软件渲染（1280x720，无认证）；Android 侧**手写 RFB 3.8 + ZRLE 客户端**（无 VNC 库）；无 virtio-gpu/gfxstream 路径。
- 音频：guest PulseAudio simple-protocol-tcp 4713 → Android 播放（仅 guest→host 出声，无麦克风）。

## 6. 网络

- QEMU：SLIRP user-mode（`ipv6=off`，**IPv6 明确禁用**）；guest 静态 10.0.2.15/24；DNS 从 kernel cmdline 传入（Android 无 /etc/resolv.conf 的坑）；ICMP 经 libslirp 非特权 socket 可用。
- AVF：crosvm **TAP + Android tethering DHCP**（udhcpc）；TCP/UDP 转发走 vsock 隧道到 guest agent。
- VPN 冲突：无任何处理代码（未知/未解决）。隐式转发（SSH 9922/VNC/音频）只绑 127.0.0.1；用户规则可选 0.0.0.0。

## 7. USB / 音频

- USB 直通**仅 QEMU**：`UsbManager` 拿 fd → QMP `add-fd`（SCM_RIGHTS）→ `device_add usb-host,hostdevice=/dev/fdset/N`；每设备运行时授权弹窗；libusb 编译开启。真实适配器仍有 open bug（#86/#85）；**AVF USB 是已知缺口（#43）**。

## 8. Android 集成

- minSdk 26 / targetSdk 36 / arm64-v8a only；AVF 路径需 Android 14+。
- 权限：INTERNET、FGS + FOREGROUND_SERVICE_SPECIAL_USE、WAKE_LOCK、RECEIVE_BOOT_COMPLETED、POST_NOTIFICATIONS、MANAGE_EXTERNAL_STORAGE（Downloads 9p）、AVF 两权限（signature|development，adb pm grant）。
- FGS `specialUse`（subtype "Podman emulation via QEMU"）+ PARTIAL_WAKE_LOCK；`podroid-launcher.c` 设 PDEATHSIG（注意：**PDEATHSIG 是线程作用域**——他们在专用永不回收的线程上 fork QEMU，修过一个隐蔽 bug）。
- **QEMU 以 `libqemu-system-aarch64.so` 名义打进 jniLibs**（extractNativeLibs=true，16KB 页对齐校验）——绕过 W^X 限制的标准做法，证实了我方推断。

## 9. 构建流水线

- Gradle：`:app` + `:terminal-emulator` + `:terminal-view`；AGP 9.1 / Kotlin 2.2.21 / Hilt / Compose。
- 规模：~22k 行 Kotlin + ~14k 行 vendored Termux Java + ~2.1k 行 C + ~1.2k shell；无 Rust；30 个 JVM 单测覆盖纯逻辑（engine pick、9p server、capabilities、DataStore 契约）。
- QEMU 在 Docker 内用 NDK r27c 交叉编译（静态 glib/pixman/libusb + Bionic shims）。**无 CI**——发布全靠维护者本机。

## 10. 许可证

- 仓库 **GPL-2.0-or-later**；栈：kernel GPLv2、QEMU GPLv2+、libslirp BSD-3、Alpine 各包、Podman Apache-2.0/GPL-2.0、TigerVNC GPLv2、PulseAudio LGPL-2.1、Termux fork GPLv2+、HiddenApiBypass LGPL-3.0。
- **复用约束**：抄代码 = 你的项目必须 GPL 兼容；架构/机制可观察、可重新实现（fd 直通 USB、9p-over-vsock、engine 路由都是可借鉴设计而非必须抄的实现）。

## 11. 成熟度

- 2,209 stars / 132 forks / 395 commits；**2026-03-16 创建，仅 6 个月**；28 个 release（约每 1–3 周一个）；~20.5k APK 下载。
- 有真实 issue 分诊（USB 固件 bug、Tensor 多核 reset 已修）。**结论：已过实验期，但未生产硬化**（无 CI、无校验和、单发行版、单 VM、单维护者核心）。

## 12. 弱点 / 惊讶点

1. **Guest root 密码是公开常量 `podroid`**，SSH 9922 可被局域网访问（用户开了 LAN 转发时）。
2. **零加密校验**：构建输入与 APK asset 均无 checksum/签名——供应链靠 TLS。
3. **无 CI**：release 不可复现（issue #64 在要求）。
4. **遗留双 rootfs 管线**：Dockerfile SECTION 1 仍往 initrd 塞完整 Alpine（旧 ttyd 时代遗物），与 squashfs 管线漂移、白白膨胀 APK。
5. **后端非对称是自认的技术债**（Downloads/USB/QMP/存储全部双实现）。
6. **反射依赖隐藏 API**：跨 OEM/AVF 版本脆弱（有 AvfReflect fallback 缓解）。
7. 硬编码：SLIRP 静态地址、root 密码、vsock 端口、hvc 槽位顺序、Xvnc `-SecurityTypes None`。
8. 内存现实：TCG 需要进程持有 GB 级 RSS，受 OOM-killer 摆布；16GB VM 选项过于乐观。
9. 无剪贴板同步、无麦克风、无 guest GPU 加速、无 IPv6、无多 VM。

## Verdict：对新项目的建议

**值得抄的设计（架构层面）**：
- VmEngine 接口 + 运行时路由 + 纯函数决策（可单测）+ 状态机守卫下的引擎切换
- squashfs(只读) + ext4(持久 upper) + overlayfs + 版本化迁移脚本
- USB 直通的 QMP add-fd / SCM_RIGHTS fd 流方案
- 9p-over-vsock（Kotlin in-process server）
- virtio-console 三通道（term/ctrl/host）+ 防抖 resize
- guest→Android 多调用 host bridge daemon
- QEMU 改名 .so 进 jniLibs + 16KB 对齐检查
- 隐式转发 vs 用户转发两类对账模型

**应避免**：硬编码密码/静态地址（改 DHCP）、无 CI 发布、双 rootfs 管线遗留、GPL 混入（若想要其他许可证——架构可学，代码有 GPL 义务）、单一发行版赌注。
