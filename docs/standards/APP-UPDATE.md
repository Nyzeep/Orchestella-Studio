# 应用内更新体验约束（APP-UPDATE）

> **状态**：项目级硬约束 (Active Hard Policy)
> **生效日期**：2026-10-30（0.6.2 起）｜**最近修订**：2026-11-06（v1.1，单一更新卡片）
> **约束范围**：所有涉及「检查新版本 / 升级提示 / 发布页跳转」的代码、文案与发布流程

---

## 1. 一条链路，一个入口

- 版本信息的**唯一来源**是 GitHub Releases API（`ReleaseSelector.RELEASES_API`），仓库地址在
  `ReleaseSelector` 里写死，其它任何域名、镜像、自建接口一律拒绝。`GitHubUpdateChecker` 在发请求前
  先比对 `apiUrl`，不在白名单直接返回错误，不打开连接。
- 升级提示的**唯一入口**是主界面右上角的「关于」按钮。除此之外不允许出现第二个小红点、横幅或弹窗式
  催促（首次启动向导、终端页、实例列表都不加）。
- 版本比较只认 SemVer，且**必须严格大于**当前安装版本：同版本重打包、降级、预发布在稳定通道都不提示。

## 2. 零遥测不可谈判

- 检查更新只发标准 GitHub 头（`User-Agent`、`Accept`），不带设备标识、不带安装 ID、不带任何埋点。
- 用户在设置里关掉「检查更新」后，**网络连接数必须为 0，本地也不写入任何检查状态**
  （`UpdateCenter.record(DISABLED)` 直接返回，有单测钉住）。
- 检查是只读的：不下载 APK、不预下载、不写入下载目录。

## 3. 触发与节流

| 场景 | 行为 |
| --- | --- |
| 主界面 `onResume` | 自动检查，受 6 小时间隔约束（`UpdateCenter.DEFAULT_INTERVAL_MS`） |
| 进入「关于」页 | 同上，受同一间隔约束；不额外开线程 |
| 点「立即检查更新」 | 手动，忽略间隔，但**仍然尊重**「检查更新」开关 |
| 并发 | 全局单飞（`UpdateCoordinator.IN_FLIGHT`），任何时刻最多一个请求 |

自动检查必须完全静默：成功不提示，失败不弹错、不写日志到界面；失败只更新节流时间戳，**不清空上一次
已知的可用版本**（网络抖一下不该让红点消失）。

## 4. 不做「忽略」入口

- 更新提示只存在于「关于」页的一张卡片上，不占用主界面空间、不打断任何流程，因此**不再提供
  「暂时忽略」**：卡片只陈述「有没有更新的版本」，装了对应的包它自然消失。
- 早期版本用 `update_ignored_version` 记住「用户跳过的那一版」；该状态与按钮已在 2026-11-06
  随单一卡片改版一并移除（用户指令：更新卡片不要「一键下载 / 可忽略」这类动作位）。旧安装里
  残留的该键不再被读取，也不参与任何判定。
- `UpdateCenter` 只保留「严格更新才提示」这一条判定；忽略状态的删除由
  `UpdateCenterTest.anAnnouncedVersionKeepsShowingUntilTheCheckSaysOtherwise` 钉住。

## 5. 交互与文案

1. 主界面「关于」按钮右上角出现主题强调色的圆点（`about_update_badge`），无数字、无动画、不抢焦点。
2. 关于页只有**一张**「版本与更新」卡片（`card_version_update`），三态：
   - 已知道有更新的版本：「有可用新版本 vX.Y.Z」+ 发布说明摘要 + 「在 GitHub 查看」；
   - 未发现更新：「尚无可用更新」+ 一句「摘要来自 GitHub Releases」的说明；
   - 设置里关了检查：「更新检查已关闭」+ 零遥测说明，检查按钮一并隐藏。
3. 卡片只有两个文字动作：「立即检查更新」（手动、忽略 6 小时间隔）与「在 GitHub 查看」
   （仅在已知更新时出现，打开本地拼装的 `RELEASES_PAGE + /tag/<tag>`）。
   **不放**「一键下载」「前往下载」「暂时忽略」这类按钮，也不弹二级「更新说明」对话框——
   摘要已经在卡片上，Release 页才是完整说明与产物的唯一去处。
4. 手动检查的结果就地更新卡片：有更新时卡片直接换态，已是最新给一句 Toast，失败给一个
   「检查更新失败」对话框（含 Releases 页出口）。
5. 文案纪律：不写「立即升级否则…」，不制造焦虑；只陈述版本号、摘要与 Release 入口。

## 6. 摘要规则（`UpdateNotes`）

发布说明是写给 Release 页的，不能整段塞进卡片：

- 丢弃：引用块（`>`，通常是元信息）、标题行（`#`）、表格、图片、分隔线、HTML 标签、代码围栏。
- 保留：列表项与正文的**文字**；链接保留文字、去掉 URL；去掉 `**`、`__`、反引号等标记。
- 上限：**5 行 / 320 字**，超出截断并补 `…`。
- 摘要为空时，卡片必须给出兜底文案（`version_update_notes_fallback`），不能出现空白区域。

## 7. 失败与边界

- 发布列表超过 100 条或响应超过 1 MiB：直接放弃，提示走 Releases 页面手动查看，不做分页拼装。
- 反向代理/中间人返回的超链接一律不采信：跳转地址由 `RELEASES_PAGE + /tag/<tag>` 本地拼装。
- 检查更新的任何异常**不得**影响主界面渲染、实例启动或安装流程；`UpdateCoordinator` 吞掉运行时异常，
  下一次触发重试。

## 8. 验收清单（每次改这里都要过）

- [ ] `UpdateCenterTest` 全绿：严格更新、失败保留、关闭零写入、节流边界、无忽略状态。
- [ ] 关掉「检查更新」后抓包 0 连接（或代码路径上 `checkForUpdate` 直接返回 DISABLED）。
- [ ] 安装 N，发布 N+1 后主界面红点出现、关于页卡片显示 N+1 与发布说明摘要；装上 N+1 后卡片消失。
- [ ] 关于页只有一张更新卡片，卡片上不出现下载/忽略按钮，也不弹二级更新说明对话框。
- [ ] 摘要不超过 5 行、不出现 markdown 符号与裸 URL。
- [ ] 红点颜色跟随主题强调色（切到构成主义红/蓝/黄时不得保持旧色）。
